# 10 · `Colossus_Run`

## 역할

- 36f, 30 fps, 1.20초, Loop, in-place.
- 플레이어를 보고 있는 동안의 추격이다. `Walk_Knuckle` 은 배회 · 수색용으로 남는다.
- 너클보행 그대로 속도만 올린 것이 아니다. **팔로 몸을 던지고 다리가 따라온다.**

## 속도 — 플레이어보다 느려야 한다

IMPORTANT: 이 클립이 이 적의 정체를 바꿀 수 있는 자리다. 기획은 6장을 「도망치며
절차를 밟는 장」으로 쓰고 이 적을 「느리다」로 정의했다. **달리기가 플레이어보다
빠르면 도망이 선택지가 아니라 지연이 된다.**

| | 속도 |
| --- | ---: |
| 플레이어 전력질주 | 4.6 m/s |
| 플레이어 걷기 | 2.8 m/s |
| **`Colossus` 달리기** | **2.60 m/s** |
| `Colossus` 배회 | 1.15 m/s |

2.60 m/s 는 **걷기(2.8)보다 아주 조금 느리고 전력질주(4.6)보다 확실히 느리다.**
걸으면 잡히고 달리면 벗어난다. 스태미너가 5초에 바닥나므로 계속 달릴 수는 없고,
그래서 도망이 성립하면서도 긴장이 남는다.

이 계산은 Crawler 속도를 5.5 에서 4.0 으로 내린 것과 같은 방식이다. 근거는
[`tech-design/decisions.md`](../../../../../tech-design/decisions.md) 의
「`Crawler` 속도를 5.5 에서 4.0 으로 내렸다」.

## 접지와 보폭

배회와 달리 **대각선 짝**으로 간다. 3점 지지를 버리고 2점으로 내려간다.

| 사지 | 위상 |
| --- | ---: |
| `FL` + `HR` | 0.00 |
| `FR` + `HL` | 0.50 |

| 항목 | 값 |
| --- | ---: |
| 접지 비율(duty) | 0.58 |
| 접지 구간 | 0.70초 |
| 한 주기 이동거리 | 1.82 m |
| **클립이 담은 지면 속도** | **2.60 m/s** |
| Unity 재생 배속 | `velocity / 2.60` |

**비접지 구간이 생긴다.** 위상 0.58 로 두 짝이 번갈아 밟으므로 주기당 두 번,
각각 최대 2프레임 동안 네 점이 모두 뜬다. `Walk_Knuckle` 의 3점 지지 규칙은
이 클립에 **적용하지 않는다.** 다만 3프레임을 넘기면 뛰는 것으로 보인다.

## 키포즈

| 프레임 | 접지 | 포즈 |
| ---: | --- | --- |
| 1 | FL + HR | 앞손 catch. 팔꿈치가 충격을 먹고 `Pelvis` 90 mm 하강 |
| 6 | FL + HR | 몸이 앞손 위를 통과한다. 흉곽이 가장 낮다 |
| 11 | FL | 뒷발이 밀어낸다. 몸이 앞으로 길어진다 |
| 14 | — | **비접지.** 최대 2프레임 |
| 19 | FR + HL | 반대 짝 catch |
| 24 | FR + HL | 몸이 통과 |
| 32 | — | 두 번째 비접지 |
| 37 | FL + HR | 1f 복제. **액션 범위는 1~37** |

## 제작값

- `Pelvis` 상하폭 **160 mm**. 배회(45 mm)의 3.5배다. 무게가 실린 질주라 위아래로
  크게 찍는다.
- 몸통 pitch ±7°, roll ±6°. 배회보다 크지만 여전히 pitch 보다 roll 이 크다.
- **팔이 주도한다.** 팔 스윙 진폭이 다리의 1.6배다. 이 적은 팔로 달리는 것이지
  다리로 달리는 것이 아니다.
- 앞손 catch 때 `Wrist` 를 먼저 세우고 `ForeArm` 이 2f 늦게 접혀 충격을 받는다.
  어깨가 무너지지 않게 `Chest` 를 유지한다.
- 뒷다리 push 는 좌우를 1f 어긋나게 해 기계적인 토끼뜀을 피한다.
- `Jaw` 는 8~14° 사이에서 흔들린다. 벌어진 채 달린다.
- `HeadBase` 는 몸통 pitch 를 **50%** 만 상쇄한다. 배회(60%)보다 적게 잡아 머리가
  더 흔들리게 둔다.
- 쌍봉은 `Chest` 를 0.5 배로 따라간다. 배회(0.6)보다 더 늦게 온다.

## 루프

`Walk_Knuckle` 과 같은 규칙이다. **모든 주기 항이 36f 를 정확히 나누는 정수
배음**이어야 하고, 1f 와 37f 의 모든 본 포즈가 같아야 한다. 재서 확인한다.

## 언제 나가나

- `IsChasing` 이 참이고 **플레이어가 현재 시야 안**일 때.
- 놓친 뒤 마지막 목격 지점으로 갈 때는 `Walk_Knuckle` 로 내린다. 안 보이는데
  달려오면 「피하는 것이지 숨는 것이 아니다」가 깨진다.
- `Roar` 직후에 이어진다. 포효 → 질주가 이 적의 발견 시퀀스다.

## 코드 계약

`NavMeshAgent.speed` 를 상태에 따라 바꿔야 한다. 현재 `Colossus.cs` 에는 속도
전환이 없다.

| 상태 | speed |
| --- | ---: |
| 배회 · 수색 | 1.15 |
| 추격(시야 안) | **2.60** |

`acceleration` 2.20 m/s² 로는 1.15 → 2.60 에 0.66초가 걸린다. 포효가 1.2초이므로
포효가 끝나고 0.66초 뒤에 최고 속도가 된다. **그대로 두는 것이 맞다** — 기획이
말한 「달아날 시간」이 실제로는 1.2 + 0.66 초쯤 된다.

## 검수

- 비접지 구간이 한 번에 2프레임을 넘지 않는다
- 2.60 m/s 직선 10 m 추격에서 접지 미끄러짐이 한 접지 구간당 5 cm 이하
- 1f 와 37f 의 모든 본 포즈가 정확히 같다
- 64px 실루엣에서 `Walk_Knuckle` 과 확실히 구분된다
- **플레이어가 전력질주로 벗어날 수 있다.** 실제로 달려서 확인한다
