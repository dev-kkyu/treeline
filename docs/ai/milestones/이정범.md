# AI 활용 마일스톤 - 이정범

## 2026-08-05 · 원샷 프로토타이핑과 Blender 에셋 제작 실험

별도의 로컬 프로젝트에서 Claude Code로 쓸 만한 프로토타입을 한 번에 뽑아낼 수
있는지 시험했다. 결과는 만족스럽지 않았다. 단순한 게임이 아니어서 그런 것으로
보인다. 요구사항이 여러 갈래로 얽힌 상태에서 한 번의 지시로 전체를 세우려 하니
어느 쪽도 제대로 서지 않았다.

Blender를 붙여 Claude의 에셋 제작 능력도 함께 실험했는데 역시 기대 이하였다.
형태가 단순한 Prop 정도는 쓸 만해 보였지만 그 이상은 손이 더 갔다.

여기서 얻은 결론은 순서를 바꾸자는 것이다. 게임이 정확히 어떻게 진행되는지를
먼저 확정하고, 거기서 필요한 에셋 목록을 정리한 다음, 차례대로 만들어 나가는
편이 낫다. AI에게 크게 한 번 맡기는 방식보다 범위를 좁혀 순서대로 맡기는 쪽이
현재로선 확실해 보인다.

## 2026-08-08 · 캐릭터 모델링 파이프라인 R&D (작업은 8/5~8/6, 저장소 밖)

별도 폴더에서 AI 모델링 경로를 세 번에 걸쳐 시험했다. 결론은 **한 도구에 전부
맡기지 말고 공정을 쪼개는 것**이다. 형태 생성과 리깅·애니메이션은 잘하는 도구가
서로 다르다.

**1단계 — Codex로 가이드 시트.** `mutual-planning/MUTUAL`에서 Codex와 함께
크리처 외형 문서와 컨셉 아트 9장을 만들었다. 턴어라운드 시트, 애니메이션 리그
시트, 4방향 이미지가 여기서 나왔고 이후 모든 단계가 이 시트를 기준으로 돌아갔다.

**2단계 — Claude Code + Blender 직접 모델링 (실패).** 같은 폴더에서 가이드만
주고 "게임용 깔끔한 토폴로지"를 요구했다. Claude는 Blender MCP 대신 헤드리스
Python 생성 스크립트를 골랐다 — 재실행이 가능해 반복 수정에 낫다는 이유였고,
판단 자체는 맞았다. 7,506쿼드에 tri/n-gon 0인 토폴로지까지는 나왔다. 다리 관절,
판갑 밀도, 발바닥 접지, 발광 셰이더를 열 번 넘게 렌더로 확인하며 고쳤는데도
결과는 프리미티브를 조합한 티를 벗지 못했다. 형태를 코드로 기술하는 방식의
한계로 보인다. 산출물은 버렸다.

**3단계 — MeshyAI + Claude Code (성공).** 가이드 시트의 4방향 이미지를
MeshyAI에 넣어 모델을 생성하고(`Meshy_AI_Celestial_Carapace`, 14,725버트), 그
결과를 Claude Code에 넘겨 리깅과 애니메이션 5종(대기·걷기·고속추격·살해·사망)을
만들게 했다. 지금 그대로 써도 되는 품질의 스켈레탈 애니메이션이 나왔다.
FBX·GLB로 내보낸 뒤 역-임포트해서 39본과 5클립이 다 들어갔는지까지 검증했다.

3단계도 순탄하지는 않았고, 오히려 여기서 배운 게 가장 많다.

- **리그 뼈대 추출.** Z-슬라이스 중심선 추적이 얇은 다리에서 끊겼다. 측지거리
  기반 스켈레톤화로 바꿨더니 필라멘트 다발이 링 중심을 끌어당겨 더 나빠졌다.
  결국 처음 방식에 밴드 스킵을 허용하는 쪽으로 돌아가 해결했다. 추출된 다리
  6개가 컨셉 아트의 LEG 1–6과 정확히 일치했다.
- **본 롤이 틀려 무릎이 접히지 않고 옆으로 벌어졌다.** 관절마다 굴곡면이 달라서
  생긴 문제였고, 각 관절의 실제 굴곡면에서 힌지축을 계산하게 고쳤다.
- **촉수 아티팩트가 연쇄로 터졌다.** IK 타깃이 지면 아래로 내려가 갈고리처럼
  말림 → 절차적 드룹+지면 클램프로 교체 → 방향이 뒤집혀 152° 킹크 → 굴곡각
  42° 상한 → 이번엔 각도 제한이 클램프 뒤에 적용돼 바닥을 뚫음(z=−0.32) →
  제약 순서를 뒤집어 지면 클램프가 항상 마지막에 오게 해서 정리됐다.
- **Blender 5.2가 레이어드 액션 체계로 바뀌어 `Action.fcurves`가 없어졌다.**
  채널백을 경유하도록 우회했다.

가장 큰 실수는 사람이 잡았다. 전방 축을 +Y로 잘못 잡아 걷기와 추격이 뒤로 가고
있었는데, Claude는 렌더를 여러 장 확인하고도 못 알아챘다. 내가 지적하자 실제
전방이 −Y임을 인정하고, 접지된 발 4개가 모두 +Y로 밀어낸다는 걸 수치로 확인해
방향을 검증한 뒤 살해·사망까지 선두 다리 쌍 기준으로 다시 썼다. **결과를 눈으로
보는 검증 단계는 사람이 쥐고 있어야 한다**는 걸 확인한 지점이다.

## 2026-08-08 · Codex로 세계관을 짓고 기획안까지 좁힌 과정 (작업은 8/5, 저장소 밖)

`drafts/이정범/mutual.md`가 나오기까지의 경로다. `mutual-planning/MUTUAL`에서
Codex와 한 세션으로 약 8시간 반, 프롬프트 47개(재전송 포함)를 썼다.

**출발은 게임이 아니라 소설이었다.** 나홍진 「호프」 줄거리를 읽히고 시작했는데,
인물·설정·전개를 그대로 각색하면 권리 문제가 생기므로 **'영감을 받은 오리지널'로
분리해 쓰라고 먼저 못박았다.** 거기서 `MUTUAL: Signal at Blackwater`가 나왔고,
기획서가 아닌 소설을 먼저 쓰게 했다.

이후는 계속 파고드는 방식이었다. 지시는 대부분 짧은 질문이었다.

- "바다는 세 번 대답했다는 게 무슨 말임? 얘네 뭐하고 있는 건데?" — 독자가 못
  알아듣는 지점을 짚자 프롤로그를 결과가 아니라 실험 목적부터 설명하도록 다시 썼다
- "ORPHEUS를 가동하면 왜 네레이드가 죽음?" — 압전성 생체 광물판과 초저주파
  공진이라는 원리가 여기서 생겼다. 되묻지 않았으면 그냥 죽는 걸로 남았을 것이다
- 추격전 요구(파피 플레이타임 같은 게 있으면 재밌겠다), 군 선발대와의 갈등 추가,
  네레이드 종족 설정집, 등장 개체별 외형 설정집, 컨셉 아트 9장, 배경·소품·차량·
  UI·조명·음향을 묶은 월드 프로덕션 패키지까지 확장됐다

**결정적인 전환은 마흔 번째 프롬프트쯤에 있었다.** "3명 팀이고 모든 에셋과 제작은
생성형·Agentic AI로 하며 주말 48시간 동안 만든다"는 전제를 그제서야 말했다. 그
직전까지 Codex가 잡아준 범위는 8~10시간 분량의 챕터 기반 세미리니어 게임이었는데,
전제를 듣자 **15~25분짜리 버티컬 슬라이스**로 단번에 줄었다. 지금 `mutual.md`에
남아 있는 범위가 그것이다.

여기서 배운 게 가장 크다. **제약을 늦게 말하면 그 전에 만든 것이 전부 과잉이 된다.**
Codex는 전제를 되묻지 않고 요구하는 대로 계속 넓혔다. 소설·설정집·컨셉 아트는
지금도 쓸모가 있지만, 범위를 먼저 말했다면 훨씬 적게 만들고도 됐다.

막힌 것 하나. 총기 이미지 생성이 안전 필터에 두 번 거절됐다. 우회하지 않고
비작동 외형 명세 문서(`WEAPON-3D-asset-spec.md`)로 대체했다.

마지막 단계는 Claude Code가 맡았다. 결과 텍스트를 넘겨 프로젝트 규칙에 맞게
정리해 커밋했다(`e6cadbe`). 이때 **원문 판단을 고치지 않고 표시만 해둔 것이 넷**
있다 — 48시간 전제가 사전 과제와 안 맞는 점, 역할 분담을 사람에 매핑하지 않은 점,
제출물인 30~60초 영상 계획이 빠진 점, 세계관 고유명사가 저장소 밖 자료에만 있어
팀원이 읽을 수 없는 점이다. 마지막 것은 이 안으로 갈 경우 반드시 풀어야 한다.
