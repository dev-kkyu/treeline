# AI 활용 마일스톤 - 임성규

## 2026-08-04 · Claude Code 개발 기반 구축

게임 제작 전에 "AI로 개발하기 위한 기반"부터 세웠다. 상태줄(모델·컨텍스트
사용률·비용 표시), force push 차단 훅, PowerShell 작성 규칙, 프롬프트 자동
로깅까지 전부 Claude에게 요구사항만 말하고 구현·검증을 맡겼다.

지시 방식은 "무엇을 원하는지"만 말하고 방법은 맡기되, 결과가 마음에 안 들면
바로 되돌리게 하는 식이었다. 상태줄은 색상·구분자·표시 항목을 대여섯 번
주고받으며 다듬었고, 한 번은 작업 전체를 원상복구시키기도 했다.

막힌 지점이 둘 있었다. 첫째, 상태줄이 빈 줄만 나왔는데 원인은 PowerShell 실행
정책이었다. 에러가 stderr로만 빠져 증상만으로는 알 수 없었고, Git Bash에서 같은
명령을 직접 실행해보고서야 잡혔다. 둘째, 프롬프트 로그의 한글이 전부 깨졌다.
stdin을 CP949로 읽은 탓이었고 UTF-8 스트림으로 직접 읽어 해결했다.

이 두 함정은 `.claude/rules/powershell.md`에 규칙으로 남겨, 앞으로 팀원이
`.ps1`을 건드릴 때 자동으로 로드되게 했다.

## 2026-08-05 · 팀 공용 설정 확장과 스택 확정

기반을 팀 단위로 넓혔다. 커밋 시 git user.name이 한글인지 검사하는 훅, 마일스톤
메모용 `/milestone` 스킬, 팀원 온보딩 체크리스트(`docs/team-setup.md`), 에셋
출처·라이선스 기록 문서를 만들었다. 기술 스택은 Unity WebGL, 프로젝트 위치는
`Mutual/`, 버전은 6.3 LTS(`6000.3.21f1`)로 확정했다.

스택 선정 과정이 흥미로웠다. Claude가 처음에 웹 네이티브를 권했는데 근거가
"Unity는 AI가 닿는 면적이 좁다"였다. Unity MCP로 씬·컴포넌트까지 조작 가능하다고
알려주자 그 근거를 스스로 접고 권고를 뒤집었다. 팀 전원이 Unreal 경험자라는
점까지 반영한 판단이었다. 근거를 대며 반박하면 결론이 바뀐다는 걸 확인한 셈이다.

막힌 지점이 셋 있었다. 첫째, 팀원이 "작업 경로에 한글이 있으면 깨진다"고 제보했는데
확인해보니 글자가 깨지는 정도가 아니라 `ConvertFrom-Json` 파싱이 실패해 상태줄
전체가 빈 값으로 무너졌다. 어제 로그 훅에서 고쳤던 CP949 문제가 상태줄에도 그대로
있었는데, 그때는 경로가 ASCII라 드러나지 않았을 뿐이었다. 같은 함정을 두 번 밟은
셈이라 입출력 인코딩을 별도 규칙으로 승격시켰다.

둘째, 우리가 만든 force push 차단 훅이 정상 커밋을 막았다. `git commit -F -`의
`-F`가 force 플래그로 오인된 것인데, 명령 전체를 한 덩어리로 검사한 탓이었다.
서브커맨드 단위로 나누고 `git`으로 시작하는 세그먼트만 보도록 고쳤다. 안전장치가
오탐하면 결국 꺼버리게 되므로 이런 수정이 중요하다.

셋째, Claude가 "커밋"만 요청받고 push까지 실행했다. 앞선 명령에 둘을 묶어둔 상태로
훅에 막혔다가 재실행하면서 범위를 재확인하지 않은 탓이다. 지적하자 변명 없이
인정하고 CLAUDE.md에 규칙으로 남겼다. 되돌리려면 force push가 필요한데 그건
자기가 만든 훅에 막혀 있어서, 사용자에게 명령을 알려주는 선에서 멈췄다.

## 2026-08-06 · Unity 프로젝트 생성과 문서 체계 구축

Unity 프로젝트를 만들고 저장소에 올렸다. 절차는 Claude에게 물어 진행했는데,
Unity Hub가 `Location\ProjectName` 경로로 만든다는 점과 Unity 6에서 `WebGL`이
`Web`으로 이름이 바뀐 것처럼 모르면 헤맸을 지점들을 미리 짚어줘서 한 번에 됐다.
프로젝트 폴더명을 정할 때는 후보를 몇 번 바꿔가며 물었고, 그 이름이 곧 Unity
Hub에 표시된다는 사실을 알고 나서 최종적으로 `Mutual`로 정했다.

이어서 기획·기술 문서를 어떻게 관리할지 정책을 잡았다. 제출물을 마감 때 새로
쓰지 않고 계속 갱신해 온 원본에서 뽑는 방식으로 정하고, 문서를 AI 환경 / 게임
기획 / 게임 기술 세 축으로 나눴다.

이 과정에서 Claude가 세 번 틀렸고 세 번 다 지적하자 바로 접었다. 처음에는
기획 문서를 담당자별로 쪼개자고 했는데, 근거가 "파일 소유권이 있으면 충돌이
없다" 였다. 같은 영역을 다른 사람이 건드릴 수 있지 않냐고 되묻자, AI 로그처럼
개인 기록에나 맞는 논리를 공동 산출물에 잘못 갖다 붙였다고 인정하고 "처음부터
쪼개지 않는다" 로 바꿨다. 두 번째는 기술 문서에 훅·규칙 같은 AI 환경 결정을
섞어 넣은 것이었고, 세 번째는 `design`과 `tech`라는 비대칭 이름이었다.
근거를 대며 반박하면 결론이 바뀐다는 것을 이번에도 확인했다.

막힌 지점은 `.gitignore`였다. `Assets/ThirdParty/`가 무시되지 않고 있었는데,
패턴 중간에 슬래시가 있으면 git이 최상위에 고정시키기 때문이었다. Claude가
직전 커밋에서 "앞에 슬래시를 안 붙이면 어느 깊이든 걸린다"는 주석까지 달아둔
상태여서 더 놓치기 쉬웠다. 프로젝트를 하위 폴더에 두기로 하면서 드러났고,
에셋을 넣는 순간 재배포 금지 대상이 그대로 커밋될 뻔했다.

우리가 만든 force push 차단 훅이 정상 커밋을 막는 일도 있었다. `git commit -F -`의
`-F`를 force 플래그로 오인한 것인데, 안전장치가 오탐하면 결국 꺼버리게 되므로
서브커맨드 단위 검사로 고쳤다.

팀원 쪽에서도 두 건이 올라왔다. 클론 후 씬에 `Global Volume`이 없다는 제보는
Unity가 빈 씬을 띄운 것이었고(빈 씬에도 카메라와 라이트는 있어서 얼핏 정상으로
보인다), `.slnx`가 미추적으로 잡힌 건 `*.sln` 패턴이 못 잡는 새 포맷이었다.
둘 다 원인을 확인하고 `docs/team-setup.md`와 `.gitignore`에 반영했다.

## 2026-08-08 · 배포 경로 확보, Unity MCP 연동, 작업을 명령으로 만들기

게임을 만들기 전에 배포부터 뚫었다. 다 만든 뒤 배포가 막히면 손쓸 시간이 없고,
프로젝트가 비어 있는 지금이 빌드도 빠르고 문제 격리도 쉽다는 판단이었다. 실제로
Decompression Fallback, `.nojekyll`, 줄바꿈 변환 차단 세 가지가 맞물려야 동작했고
하나라도 빠지면 조용히 실패하는 종류였다. 빈 씬이 브라우저에 뜨는 것까지 확인한
뒤 그 이유를 `docs/tech-design/decisions.md`에 남겼다.

Unity MCP도 붙였다. Claude가 처음 권한 건 Unity 공식 MCP였는데 유료 패키지에
묶여 있다는 지적을 받고 CoplayDev 쪽으로 바꿨다. 붙이고 나서도 두 번 더 틀렸다.
"Unity를 열면 서버가 자동으로 뜬다"고 문서에 적었지만 실제로는 매번 `Start
Server`를 눌러야 했고, 이건 팀원이 직접 확인해서 알려줬다. 서버를 끈 상태와 켠
상태에서 각각 호출해보고서야 문서를 고쳤다. `Auto-Start` 옵션이 있다는 것도
Claude가 아니라 사용자가 찾아냈다.

지운 설정이 되살아나는 것도 발견했다. 개인 설정에 중복으로 등록된 항목을
지웠는데, 패키지가 서버를 켤 때마다 클라이언트 설정을 다시 쓰는 구조였다.
지우는 게 무의미하다는 걸 알고 나서 `.mcp.json`을 공용으로 유지하기로 하고,
왜 중복을 감수하는지를 문서에 적었다.

반복될 작업은 규칙 대신 명령으로 만들었다. `/design`, `/decision`, `/deploy`가
이번에 추가돼 `/milestone`까지 넷이 됐다. 규칙은 바쁘면 건너뛰지만 명령은
실행하면 끝난다는 판단이고, `/milestone`이 실제로 그렇게 쓰이는 걸 보고 나머지도
같은 방식으로 옮겼다.

기획은 아직 못 정했다. 셋이 한자리에서 AI와 논의하면 결국 한 사람만 말하게
된다는 문제를 사용자가 제기해서, 각자 초안을 쓰고 나중에 비교하는 방식으로
규칙을 잡았다. 이때 여러 안의 좋은 부분만 뽑아 합치면 서로 맞물리지 않는다는
점을 규칙에 못박았다. 뼈대가 될 안을 하나 고르고 나머지는 그 위에서 성립하는
것만 이식하도록 했다.
