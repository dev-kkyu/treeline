# MUTUAL: Signal at Blackwater — 버티컬 슬라이스

이정범이 낸 기획안이다. **팀에서 합의된 것이 아니다.** 비교를 위해 올린 것이며,
논의를 거치기 전까지 `docs/game-design/overview.md` 에 반영하지 않는다.

이미 만들어둔 MUTUAL 세계관 전체를 구현하는 것이 아니라, **가장 강력한 경험
하나를 실제로 플레이 가능하게 증명하는** 범위를 정하려는 안이다.

IMPORTANT: 이 안은 **48시간 제작**을 전제로 쓰였다. 이 저장소는 본선이 아니라
**사전 과제** 프로젝트이므로 일정 계산이 그대로 맞지 않는다. 「48시간 일정」은
본선 조건을 가정한 것으로 읽고, 사전 과제에 쓸 때는 일정을 다시 잡아야 한다.
범위·시스템 목록·제외 목록은 일정과 무관하게 그대로 유효하다.

IMPORTANT: 등장하는 세계관 고유명사(ORPHEUS, 네레이드, 윤서진, 케슬러, 오언)는
저장소 밖 자료에 있다. 팀원이 읽을 수 없으므로, 이 안으로 갈 경우 그 자료를
`docs/game-design/` 아래로 옮겨야 논의가 된다.

## 권장 프로젝트 범위

48시간·3명·AI Native 제작이라면, **8~10시간짜리 본편이 아니라 15~25분 분량의
완결된 버티컬 슬라이스**가 적당하다.

### 한 줄 정의

> 폐쇄된 양식장에서 실종자를 수색하던 플레이어가 괴물을 발견하고, 군의 선제
> 사격으로 시작된 추격에서 살아남아 환경 장치를 연계해 괴물을 처치한 뒤
> 충격적인 진실을 확인하는 1인칭 공포 게임.

### 분량

| | |
| --- | --- |
| 첫 플레이 | 20~30분 |
| 재도전 | 10~15분 |
| 빌드 | WebGL 데스크톱 |
| 공간 | 폐쇄 양식장 한 곳 |
| 괴물 | 한 마리 |
| 인간 NPC | 3명 |
| 엔딩 | 기본 1개, 여유가 있을 때 짧은 분기 1개 |
| 핵심 추격전 | 1회 |
| 환경 처치전 | 1회 |
| 짧은 인게임 연출 | 3~4개 |

모바일 WebGL 까지 동시에 대응하지 말고 Chrome · Edge 데스크톱을 우선 목표로 잡는
편이 안전하다. Unity Web 플랫폼은 C# 관리 스레드에 제약이 있고, 브라우저
메모리 · 오디오 · 그래픽도 네이티브 빌드보다 제한되므로 시스템 수를 줄여야 한다.
[Unity 6.3 Web 기술 제한](https://docs.unity3d.com/6000.3/Documentation/Manual/webgl-technical-overview.html)

## 데모의 전체 진행

### 1. 진입 — 3분

플레이어 윤서진과 군 선발대 3명이 정전된 양식장에 들어간다.

- 이동, 시점, 손전등
- 무전 대화
- 간단한 문 열기
- 피와 파손 흔적
- "실종자가 안에 있다" 는 명확한 목표

### 2. 탐색 — 5분

플레이어가 제어실 전력을 복구하고 수조 기록을 확인한다.

- 퓨즈 또는 차단기 퍼즐 하나
- 조사 가능한 문서 2개
- 신호 분석 장치의 축약형 미니게임 하나
- 배관 속에서 이동하는 괴물의 예고
- 체크포인트

ORPHEUS 전체 시스템은 넣지 않는다. 화면이나 기록에서 이름만 보여주고 본편
떡밥으로 남긴다.

### 3. 최초 조우와 갈등 — 3분

괴물이 실종된 오언을 감싸고 있는 모습이 드러난다. 윤서진은 사격 중지를 요구하지만
케슬러 측 병사가 발포한다.

- 플레이어 시점을 고정하지 않는 인게임 컷신
- NPC 3명과 괴물만 사용
- 대사 30~45초
- 총격을 맞은 괴물이 쓰러진 듯하다가 인간을 인식
- 감각기관이 열리며 추격 상태로 전환

**여기가 데모의 대표 장면이다.**

### 4. 추격 — 5~7분

괴물이 천장, 배관, 수조 사이를 이용해 생존자들을 추격한다.

필수 이벤트:

- NPC 한 명이 플레이어 앞에서 사망
- 괴물이 잠긴 문을 부수고 진입
- 플레이어가 좁은 통로 아래로 미끄러져 탈출
- 뒤를 돌아보면 괴물이 몸을 접어 통로로 들어옴
- 괴물이 직선으로만 따라오지 않고 앞쪽 환기구에서 재등장
- 마지막 안전문을 수동으로 닫음

파피 플레이타임식 인상을 주는 핵심은 길고 복잡한 AI 가 아니라 **스크립트 재등장,
문 파괴, 앞질러 나타나는 연출**이다. 짧은 기간에는 완전 자율 추격 AI 보다 NavMesh
추격과 정해진 이벤트 지점을 조합하는 편이 낫다.

### 5. 환경 처치전 — 5분

총으로 괴물을 죽이는 것이 아니라, 시설 장치 세 개를 순서대로 작동시킨다.

1. 증기 밸브를 열어 괴물을 수조 구역으로 몰아냄
2. 양수 펌프로 바닥을 침수시켜 움직임을 제한
3. 화물 크레인의 전력선을 떨어뜨려 감전시킴

플레이어는 장치를 작동하는 동안 괴물을 피해야 한다. NPC 한 명이 사격으로 시간을
벌다가 죽거나 중상을 입는다.

복잡한 보스 AI 대신 다음 상태만 구현하면 된다.

- 추격
- 피격 반응
- 경직
- 장치 파괴
- 최종 사망

### 6. 반전과 종료 — 2분

죽은 괴물의 몸이 오언에게서 떨어진다. 오언은 살아 있으며, 괴물이 그를 먹은 것이
아니라 **치료하고 있었다**는 사실이 드러난다.

마지막으로 무전기에서 ORPHEUS 가동 명령이 들린다.

> "Blackwater 전역에 공격 신호를 송출한다."

화면 암전 후:

> `MUTUAL: Signal at Blackwater`

짧아도 이야기가 완결되면서 본편을 궁금하게 만든다.

## 48시간 일정

> 본선 48시간 조건을 가정한 계산이다. 사전 과제에는 그대로 쓸 수 없다.

| 구간 | 할 일 |
| --- | --- |
| **0~4h** | 범위 동결, 저장소 · Unity 프로젝트 생성, URP · WebGL 설정, 양식장 전체 블록아웃, 플레이어 이동, **실제 WebGL 빈 빌드 성공** |
| **4~12h** | 전체 구간을 회색 박스로 처음부터 끝까지 플레이 가능하게, 상호작용, 목표 진행, 괴물 임시 캡슐 추격, 환경 처치, 임시 엔딩 |
| **12~24h** | 괴물 모델 · 리깅 · 애니메이션, 환경 에셋 교체, NPC 배치, 최초 조우 연출, 추격 이벤트, 기본 사운드 |
| **24~34h** | NPC 사망 연출, 보스전 연출, 조명 · VFX, 음성 · 자막, UI, 체크포인트, 결말 연출 |
| **34~42h** | WebGL 최적화, 텍스처 · 오디오 압축, 불필요한 에셋 제거, Chrome · Edge 테스트, 로딩 · 메모리 · 입력 오류 수정 |
| **42~48h** | **신규 기능 금지.** 치명적 버그 수정, 난이도와 길 찾기 개선, 최종 빌드, 호스팅 테스트, 스크린샷 · 설명 작성, 제출용 빌드 백업 |

**12시간 시점에 게임 전체가 작동해야 한다.** 회색 박스라도 처음부터 끝까지
플레이되는 상태를 먼저 만들고, 그 위에 살을 붙인다.

## 성공 기준

1. 링크를 열고 브라우저에서 정상 실행된다
2. 별도 설명 없이 목표와 조작을 이해한다
3. 괴물이 총격 이후 인간을 위협으로 인식했다는 전환이 보인다
4. 추격전에서 최소 한 번 강한 공포를 느낀다
5. 괴물이 오언을 치료하고 있었다는 반전이 이해된다

결론적으로 추천 범위는 **"양식장 괴물 사건만 다룬 20분짜리 완결형 프롤로그"**다.
현재 만들어둔 세계관 · 인물 · 무기 · ORPHEUS · 네레이드 자료는 대부분 본편용
참고자료로 두고, 이번 제작에서는 양식장 구간에 필요한 약 20% 만 사용한다.

## 아직 안 정한 것

- **제출 영상** — 30~60초 플레이 영상이 제출물인데 이 안에는 영상 계획이 없다.
  20~30분 분량에서 어느 구간을 뽑을지, 그 구간을 위해 따로 만들 것이 있는지
- **사전 과제 일정** — 위 48시간 표를 사전 과제 기간에 맞게 다시 잘라야 한다
- **세계관 자료의 위치** — 고유명사를 팀이 읽을 수 있게 저장소로 옮기는 일
- **엔딩 분기** — "여유가 있을 때" 라고만 두었다. 컷라인 대상인지 명확히

## 팀에 물어볼 것

1. 이 안으로 갈지, 다른 사람 안과 섞을지
2. 20~30분 분량이 사전 과제 기간에 실제로 가능한지 — 이 안의 최대 위험이다
3. 인게임 컷신 · 음성 · 자막까지 갈지, 자막만으로 줄일지
