# 장별 분위기 점검 — 기획이 요구하는 것과 씬에 있는 것

기획서가 각 장에 **다른 분위기**를 요구한다. 그것이 실제로 씬에 있는지 재고,
어긋난 곳을 적는다. 3 · 4 · 5장은 지어진 뒤에 같은 방법으로 본다.

기획 원본은 [`../game-design/treeline.md`](../game-design/treeline.md) 「여섯 장소」,
표면 방침은 [`world-assets.md`](world-assets.md) 에 있다.

## 어떻게 쟀나

1. 씬을 열어 **안개 · 환경광 · 조명**을 읽는다 (세기 · 색 · 켜짐 여부)
2. 머티리얼별 **겉넓이**를 재서 무엇이 화면을 덮는지 본다. 개수는 오해를 부른다
3. 플레이어 시작 위치에서 **세 지점을 렌더**한다. 손전등은 그 장의 상태에 맞춘다
4. 기획서의 그 장 문단과 하나씩 대조한다

IMPORTANT: 촬영용 카메라를 새로 만들면 **씬의 카메라 설정이 안 따라온다.** 처음에
그렇게 찍어서 6장 하늘이 대낮처럼 파랗게 나왔고, 씬이 잘못된 줄 알았다. 실제로는
`clearFlags` 가 기본값 `Skybox` 였을 뿐이고 씬은 이미 `SolidColor` 로 맞춰져 있었다.
**`Camera.main` 의 `clearFlags` · `backgroundColor` · `fieldOfView` 를 베껴서 찍는다.**

## 1장 관제동 — 「아무도 없다」

기획은 이 장을 **평범한 곳**으로 두었다. 「계기판이 돌아가고 커피가 아직 따뜻한데
사람이 없다」이고, 영상 몫도 「평범한 관제실, 그리고 창밖의 그림자」다. **여기서
무서운 것은 어둠이 아니라 어긋남**이라, 다른 장과 반대로 밝아야 한다.

| | 실측 |
| --- | --- |
| 안개 | `ExponentialSquared` 0.017 (90% 가림 89 m) · 색 (0.72, 0.76, 0.82) |
| 환경광 | Trilight (0.30, 0.33, 0.38) |
| 조명 | 12 개 켜짐, 세기 합 20.3 (Directional 1.1 · 천장등 4 · 집중 스폿 3 · 은은한 것 2) |
| 손전등 | **꺼짐** — 줍기 전이다 |
| 화면 밝기 | 0.20 / 0.19 / 0.18 |

**조명 구성은 기획대로다.** 전기가 들어와 있고 손전등이 꺼져 있다. 콘텐츠도
거의 다 있다 — 커피잔 2, 근무표, 무전 일지, 끌린 자국 10, 콘솔 7, 의자 3,
서치라이트(`SustainedDevice`), 창 4.

**창밖 실루엣도 있다.** `Colossus_Motion` · `Silhouette` 이 `(0, 2, 44)` 에 꺼진 채
대기하고 있다. 서치라이트로 켜는 연출이다.

### 고친 것 — 바닥이 물바다였다

`W_concrete_floor` 는 **젖은** 변주다. 팀이 「완전 호러」라고 한 그 텍스처인데,
1장 실내 21 개 면에 그대로 깔려 있어 관제동이 통째로 물에 잠긴 것처럼 보였다.
「커피가 아직 따뜻한 곳」이 아니라 이미 버려진 곳으로 읽힌다.

범인은 얼룩이 아니라 **smoothness** 였다. 젖은 변주는 낮은 자리를 0.66 까지
올리는데 그 정반사가 광원을 되쏘아 물로 읽힌다. 마른 변주
(`concrete_floor_dry`, 최대 0.29)를 만들어 A/B 로 확인했다.

### 남은 것

- **화면 밝기 0.19 는 「평범」이라기엔 어둡다.** 조명은 12 개 있는데 천장등이
  1.1 이고 환경광이 0.30 이다. 기획의 대비 구조(1장 밝음 → 2장 캄캄)를 살리려면
  1장을 더 올리는 쪽이 맞다. **조명 값은 이 문서에서 바꾸지 않았다** — 씬 작업은
  일괄로 하기로 했다
- **「계기판이 돌아간다」가 없다.** 콘솔은 정적 모델이고 씬에 회전 · 점멸 스크립트가
  없다 (`FlickerLight` 하나뿐). 움직이는 것이 하나도 없으면 「방금까지 사람이
  있었다」가 안 선다
- `Snow_Ground` 가 300 m 인데 텍스처 한 장이 2.9 m 다 — **105 회 반복**이라
  창밖에 격자 무늬가 보인다. `SurfaceTiling.perMeter` 를 낮춘다

## 2장 숙소동 — 「처음 만난다」

기획은 **정전**이고 손전등만이다. 「좁은 복도」, 「무기가 없다」, 도망칠 길이 하나.

| | 실측 |
| --- | --- |
| 안개 | 0.070 (90% 가림 22 m) · 색 (0.00, 0.00, 0.01) — 거의 검정 |
| 환경광 | Flat (0.004, 0.005, 0.007) — 사실상 0 |
| 조명 | Directional **꺼짐** · 비상등 1.4 (붉은색) · 깜빡이 세기 0 |
| 화면 밝기 | 0.076 / 0.081 / 0.079 |

**기획대로다.** 1장의 0.19 대비 0.08 로 절반 이하이고, 유일한 색광이 붉은
비상등이다. 장치도 다 있다 — 셔터 레버, 히터, 배전함, 얼음(`IceMelt`),
숨는 방, 사물함 13, 이층침대, `Crawler` 하나.

### 표면은 손대지 않았다

처음에 「복도 벽이 도장 철판이라 밋밋하다」고 진단했는데 **틀렸다.** 벽은
`W_concrete_wall` 이고, `W_painted_steel` 84 개는 전부 얇은 트림이다 — 그중 48 개가
`Seam_L`·`Seam_R`, 즉 **팀이 패널 이음매를 지오메트리로 이미 만들어 두었다.**

머티리얼 **개수**를 세고 벽이라고 단정한 것이 잘못이었다. 겉넓이로 재면
`W_concrete_wall` 이 48.6% 로 압도적이고 도장 철판은 4.3% 다. **개수가 아니라
면적을 본다.**

### 남은 것

- 바닥은 1장과 같은 젖은 변주를 쓴다. 2장은 얼음과 성에가 있는 장이라 **젖어
  보이는 것이 틀리지 않다.** 일괄 작업 때 사람이 고른다
- `Floor` 오브젝트(3 × 50 m)가 URP 기본 `Lit` 머티리얼을 쓴 채 `y = -1` 에 있다.
  복도 바닥보다 0.5 m 아래라 안 보이지만, 복도를 큐브 모듈로 다시 지으면서
  남은 것으로 보인다. 확인 후 지울지 정한다

## 6장 삭도 승강장 — 「큰 것」

기획은 실외 · 밤이고, **절차를 밟는 동안 조명이 켜져 위치가 드러난다.**

| | 실측 |
| --- | --- |
| 안개 | 0.020 (90% 가림 76 m) · 색 (0.06, 0.08, 0.10) |
| 환경광 | Trilight (0.115, 0.145, 0.190) |
| 조명 | 8 개 (붉은 비상등 4 · 객실등 · 주입구등) · Directional **0.2** 의 푸른 달빛 |
| 하늘 | 카메라 `SolidColor` (0.06, 0.08, 0.10) — **안개색과 같다** |
| 화면 밝기 | 0.13 / 0.12 / 0.10 |

**하늘 처리가 정확하다.** 안개색과 배경색이 같아 지평선이 사라진다 — 눈보라
R&D 에서 정답이라고 결론 낸 바로 그 방법을 팀이 이미 쓰고 있었다.

`SiteLights` 가 자식 10 개를 달고 **꺼진 채** 대기한다. 기획의 「배전반을 투입한다 →
조명이 켜져 위치가 드러난다」가 구조로 들어와 있다. 절차 셋도 다 있다 —
`CarrySlot`(연료 운반) · `IceMelt`(케이블 히터) · 배전반 레버.

### 남은 것

- **제설포가 없다.** 기획의 6장 피날레(「사면에 대고 쏜다. 눈이 무너져 내려와
  그것을 삼킨다」)를 만드는 물건인데 비활성 포함해도 씬에 없다. 이건
  [`decisions.md`](decisions.md) 의 「6장 마지막의 시점 전환은 3 · 4 · 5장이 붙을
  때로 미룬다」에 따라 **예정된 미구현**이다. 5장 작업과 같이 온다
- 눈 지형이 겉넓이의 96.8% 다. `W_snow` 는 알베도 대비 0.020 으로 가장 낮아
  밤에는 형태가 거의 안 읽힌다. 걷는 자리에 `snow_packed` 를 섞으면 발밑이 산다
- `Valley_Floor` 는 텍스처 한 장이 8.3 m 로 1장(2.9 m)보다 낫다. **1장을 여기에
  맞춘다**

## 표면 쪽 조치

| 만든 것 | 왜 |
| --- | --- |
| `concrete_floor_dry` | 실내가 물바다로 보이던 것. 1장에 검증 |
| `steel_panel` | 넓은 실내 벽용. 이음매를 지오메트리 없이 얻는다 |

두 머티리얼은 만들어 두기만 했고 **씬에는 안 입혔다.** 표면 입히기는 팀 작업이
끝난 뒤 일괄로 한다.

## 콘텐츠 · 모델로 넘길 것

소품 목록은 [`props.md`](props.md) 에 있다. 아래는 이번 점검에서 나온 것이다.

| 장 | 무엇 | 왜 |
| --- | --- | --- |
| 1 | **움직이는 계기 · 점멸 표시등** | 「계기판이 돌아가고」. 움직이는 것이 하나도 없어 「방금까지 사람이 있었다」가 안 선다. 모델이 아니라 **회전 · 점멸 스크립트**면 된다 (4장 `Spin.cs` 재사용) |
| 1 | 조명 세기 재조정 | 밝기 0.19 로는 「평범한 관제실」이 안 된다. 2장(0.08)과의 대비가 이 장의 장치다 |
| 6 | **제설포** | 6장 피날레의 물건. 5장에서 한 번 쓰고 6장에서 다시 쓴다 |
| 6 | 지면에 `snow_packed` 섞기 | 밤 + 대비 0.020 이면 발밑이 안 읽힌다 |
| 1 · 6 | 야외 지면 `perMeter` 낮추기 | 1장은 105 회 반복이라 격자가 보인다 |
| 전 장 | `Player/Body` 가 기본 회색 머티리얼 | 1 인칭이라 안 보이지만, 주인공 FBX 가 들어왔으므로 정리할 자리다 |

## 계측하며 두 번 틀린 것

**`FindObjectsByType` 는 비활성 오브젝트를 건너뛴다.** 이걸 잊고 「1장에 Colossus 가
없다」는 결론을 냈는데, 비활성까지 포함해 다시 찾으니 `Silhouette` 이 꺼진 채
대기하고 있었다. 6장 `SiteLights` 도 같은 이유로 안 잡혔다.

**이 프로젝트에서 「꺼져 있는 것」은 대개 연출의 일부다.** 절차로 켜지는 조명,
서치라이트가 부르는 실루엣, 나중에 나타나는 적. 그러니 **비활성을 빼고 세면
있는 것을 없다고 하게 된다.** 규칙에도 적어 두었다
([`.claude/rules/unity-mcp.md`](../../.claude/rules/unity-mcp.md)).
