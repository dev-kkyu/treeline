# Treeline — 팀원 롤 기술서

**NHN GAME X AI HACKATHON 사전 과제 · Team SBD (3인)**

이 문서는 기억으로 쓰지 않았다. 개발 내내 쌓인 세 근거 — 커밋 기록
(`git log --author`), 각자의 작업 메모(`docs/ai/milestones/`), 프롬프트 원본
(`docs/ai/prompts/`) — 를 마감 시점에 합성한 것이다.

Team SBD, 3인.

IMPORTANT: **위 「코어」는 처음 배정한 명목이고, 실제로는 크게 달라졌다.**
아래 [「실제 담당 영역」](#실제-담당-영역)을 본다. 특히 **적 리깅은 A 다.**

2026-08-08 에 배정했다. 그 전까지 쓰던 구분(월드 / 전투 · 기획 / 기믹)은
기획이 정해지지 않은 상태에서 임시로 나눈 것이라 폐기했다.

**팀 이름은 세 사람의 이름에서 왔다** — **S** 성규 · **B** 정범 · **D** 도한.
2026-08-10 에 `Team SBJ` 에서 바꿨다.

IMPORTANT: **팀 이름의 `S · B · D` 와 담당 구분의 `A · B · C` 는 서로 다른
것이다.** 겹치는 `B` 가 가리키는 사람까지 다르다 — 팀 이름의 `B` 는 **정범**,
담당의 `B` 는 **도한**이다. 이 저장소의 문서에서 `A` · `B` · `C` 는 언제나
**담당**을 뜻한다.

## 작업 분담 — A · B · C

기획 확정(2026-08-08) 후 기획서의 「만들 시스템」과 「만드는 순서」를 기준으로
나눴다. 각자 **코어 하나 + 장 하나**다. 개발은 0단계(골격) → 1단계(관통) →
2단계(1 · 2 · 6장 기믹) → 3단계(3 · 4 · 5장) 순서로 진행했고, 단계마다 담당을
다시 배정했다.

### 1단계 — 관통

완료 기준은 **처음부터 끝까지 걸어서 엔딩에 도달하고 죽을 수도 있는 것**이다.
회색 박스여도 된다. 여기까지 되면 즉시 빌드해 배포한다.

| | | 만드는 것 |
| --- | --- | --- |
| **A** | 이정범 | 1인칭 이동 · 카메라 · 손전등 · 체력 3칸 · 권총 1종 · 탄약 · 피격 판정 |
| **B** | 김도한 | 적 1종(기는 것) 추격 · 공격 · 사망. 그리고 AI 모델 생성 → 리깅 파이프라인 검증 |
| **C** | 임성규 | 1 · 2 · 6 회색 박스, 문 · 레버 최소 상호작용, 씬 전환 · 사망 · 재시작 · 엔딩 |

IMPORTANT: **A 는 `Player.prefab` 을 완성 전에 먼저 올린다.** 캡슐에
`CharacterController` 와 `Player` 태그만 붙은 껍데기여도 된다. B 의 적은 추격할
대상이 필요하고 C 의 관통 확인에는 Player 와 Enemy 가 둘 다 필요하다. 1단계에 남은
유일한 대기 관계이므로 여기서 막히면 셋이 같이 선다.

IMPORTANT: **적 모델이 늦어져도 1단계는 진행되어야 한다.** B 는 캡슐로 추격 ·
공격 · 사망까지 완성하고 모델은 나중에 갈아끼운다. 파이프라인 검증이 1단계를
막으면 안 된다.

### 2단계 — 1 · 2 · 6 에 기믹

장을 한 명씩 인수한다. 회색 박스는 C 가 만들었지만 살을 붙이는 것은 각자다.

| | | 담당 장 | 붙이는 것 |
| --- | --- | --- | --- |
| **A** | 이정범 | 6장 승강장 | 삭도 절차, 산탄총, 엔딩 연출 |
| **B** | 김도한 | 2장 숙소동 | 첫 조우 연출, 그리고 `Colossus`(큰 것) |
| **C** | 임성규 | 1장 관제동 | 장치 3패턴 컴포넌트, 배터리, 양손 운반 |

IMPORTANT: **2단계에 만드는 적은 `Colossus` 하나다.** `Clinger`(매달린 것)는 4 ·
5장에 나오므로 3단계다. 기획의 「셋을 동시에 진행하면 셋 다 미완성이 된다」를
적에도 그대로 적용한다. 그리고 `Colossus` 는 A 의 6장이 기다리는 물건이므로 2단계
안에서도 먼저 나와야 한다.

C 가 장치 3패턴 컴포넌트를 먼저 만들어 공유하면, A 와 B 는 파라미터만 바꿔
자기 장에 쓴다.

### 3단계 — 3 · 4 · 5 ✅

2026-08-09 에 배정했고 **2026-08-10 에 셋 다 들어갔다.** 컷라인 1순위였던 5장까지
만들었으므로 **여섯 장이 전부 있다.** 아래는 배정 당시의 근거를 그대로 남긴 것이다.

| | | 담당 장 | 왜 |
| --- | --- | --- | --- |
| **A** | 이정범 | **4장 발전동** | **`Clinger` 의 에셋과 애니메이션을 A 가 처음 넣는다.** 4장은 그것이 전부인 장이고, 천장에서 떨어지는 동작은 클립과 레벨이 서로 맞아야 한다. 만든 사람이 놓는 것이 맞다 |
| **B** | 김도한 | **3장 연료 갱도** | **총기 시스템이 이미 들어가 있어** 이 장이 무기 구현을 기다리지 않는다. 남은 것은 통로 구조 · 연료 배치 · 인화 연출인데, 불은 B 가 만든 파티클 키트가 그대로 쓰인다 |
| **C** | 임성규 | **5장 외부 철탑** | 컷라인 1순위라 마지막에 붙인다. 자를 때 C 의 작업만 버려지므로 A · B 의 진행을 막지 않는다 |

**2 · 3단계에서 실제 작업이 명목 역할과 달라진 것을 반영했다.** 배정은 표가 아니라
그렇게 굳은 자리를 따랐다. 무엇이 어떻게 달라졌는지는
[「명목 역할과 실제가 달라졌다」](#명목-역할과-실제가-달라졌다) 에 있다.

IMPORTANT: **적 리깅은 이제 A 다.** 명목 역할에서 적은 B 이지만 실제로는 B 가
모델링 시트를 만들고 **A 가 리깅과 애니메이션을 붙이는 분업**으로 굳었다
(`Crawler` · `Colossus` 둘 다 그랬다). 4장이 A 로 간 근거가 그것이다.

**순서를 지킨 것이 값을 했다.** C 는 3 · 4장이 끝난 뒤에 5장을 잡았다. 컷라인
후보에 사람을 먼저 묶으면 정작 잘라야 할 때 남은 둘이 덜 완성된 채로 남기
때문이다. 그리고 야외 설원은 **B 가 타이틀 · 엔딩에서 만든 것을 프리팹으로
넘겨받았다** — 5장에서 가장 비싼 부분이 이미 만들어져 있었다.

**6장 마무리는 A 가 가져갔다.** 5장이 붙은 뒤 6장에 얹기로 했던 제설포 피날레와
시점 전환 컷을 A 가 6장 재구축과 함께 처리했다. 원래는 6장의 실질 소유가 C 라고
적어 두었는데, 엔딩 연출이 `Colossus` 애니메이션과 한 덩어리라 **적을 만든
사람에게 가는 편이 맞았다.**

IMPORTANT: ~~**A 는 레벨을 처음부터 지어본 적이 없다.**~~ 4장을 짓고 6장을 다시
지으면서 해소됐다. 진입 장벽이 낮았던 것이 컸다 — Meshy 소품 프리팹 30종,
`SurfaceTiling`, `/prop` 절차, 참고할 장 셋.

### 이정범 — 플레이어 · 캐릭터 리깅 · 4 · 6장

**플레이어 캐릭터를 통째로 만들었다.** `PlayerMotor` · `PlayerLook` ·
`PlayerInputReader` · `PlayerHealth` · `PlayerHud` · `PlayerInteractor` ·
`PlayerWeapon` · `WeaponSwitcher` · `Flashlight` · `PlayerFootsteps` — 이동 ·
달리기 스태미너 · 웅크리기 · 점프 · 시점 · 체력 3칸 · 사격과 재장전 · 상호작용 ·
손전등이 전부 여기서 나온다.

**캐릭터 리깅과 애니메이션 전량.** 주인공 전신 리그와 1인칭 팔을 세우고 클립
17종 · 전신 4종 · 손 포즈 12종을 만들었으며, 무기를 손 본에 물렸다. 적 3종의
리깅도 전부 이쪽이다 — `Crawler` 6종, `Colossus` 15종, `Clinger` 9종. Blender 를
파이썬 스크립트로 몰아 만들었고, 입력은 김도한이 만든 모델링 시트다.

**4장 발전동을 지었다.** 공간 · 동선 · NavMesh 부터 차단기 사슬 · 환기 팬 ·
발전기 예열 · 축전지실 수소 폭발까지. `Clinger.cs` 와 천장 낙하도 여기서 나왔다.

**6장 승강장과 엔딩.** 2단계 골격을 짓고, 8/10 에 절차 사슬 · 케이블카 문 ·
탑승 연출로 통째로 다시 지었다. 엔딩 연출 전체가 이쪽이다 —
`CableCarDeparture` · `CableChase` · `Ch6Boarding` · `CableCarDoor` · `Letterbox`.

**마지막에 손맛을 얹었다.** 여섯 장이 다 선 뒤에야 보이는 것들이다 — 총 반동에
시야각과 떨림(`WeaponVfx`), 날아가는 예광탄과 벽 탄착(`ShotTracerVfx` ·
`ShotImpactVfx`), 맞을 때 기우는 화면과 죽을 때 무너지는 카메라(`PlayerLook`),
암전(`ScreenFade`), HUD 셋의 반응(`HudFeel` · `HealthPipsFeel` ·
`StaminaBarFeel` · `AmmoInfinityMark`), 조작키 가이드(`ControlsPage`),
조준 설명(`AimNote`). **값은 다 맞는데 화면에서 아무 일도 안 일어나 보이던
자리들**이고, 이 게임이 「돌아간다」에서 「해볼 만하다」로 넘어간 구간이다.

### 김도한 — 적 · 사운드 · 연출 · UI · 3장

**적 3종의 코드와 규격.** `Crawler` · `Colossus` 의 상태 기계(배회 · 조사 ·
추격 · 수색 · 사망), 청각 판정, 애니메이션 이벤트 중계. 그리고 **적 3종 모델링
시트** — 이정범의 리깅이 그것을 입력으로 받았다.

**사운드 전량.** 오디오 파일 137개를 AI 로 생성하고 컴포넌트에 배선했다.
발소리 · 무기 · 적 · 상호작용 · 장치 · 앰비언스 · 음악 · 추격 음악 전환까지.

**연출과 VFX.** 타이틀 · 엔딩 설원 씬, 배경 능선과 나무, 마우스 시차, 파티클
키트, 혈흔, 입김, 눈보라, 그리고 깊이에서 월드 좌표를 복원하는 `HeightFog`
셰이더.

**UI 메뉴 계통.** `PauseScreen` · `MenuChrome` · `MenuPager` · `SettingsPage` ·
`MenuTheme` · `GameSettings`, 크레딧, 장별 목표 안내(`HudGuideText`). 타이틀 ·
엔딩 · 일시정지 세 화면이 같은 부품을 쓰게 정리한 것도 여기다.

**3장 연료 갱도를 지었다.** 아치 단면을 뽑아 갱도를 만들고, 직선 한 줄이던 것을
경비실 · 펌프실 · 낙반 우회로로 갈랐다. 소탕 격리 셔터(`ClearOut`)도 이쪽이다.
**2장 숙소동 복도도 한 번 다시 세웠다** — Blender 로 모델링해 레퍼런스 분위기에
맞춘 판인데, 나중에 큐브 모듈로 되돌아갔다. 버려진 것이 아니라 그때 정한 분위기가
남았다.

**1인칭 팔을 게임에 붙였다**(`ArmsAnimator`). 리그는 이정범이 만들었고, 그것이
화면에서 총을 제대로 들도록 파지 · 총구 · 탄도를 맞춘 것은 김도한이다.

**제출 영상 1차본**을 Unity 캡처부터 자막까지 자동화해 뽑았다.

**마감 직전에 두 가지를 되돌렸다.** 4장이 처음부터 다 보여 기획의 「전력이 들어오며
드러난다」가 죽어 있던 것을 정전 상태로 되돌렸고(여섯 장 중 유일하게
`BlackoutLighting` 이 없었다), 브라우저가 가져가는 `ESC` · `Ctrl` 을 조작에서 빼고
멈춤을 `Tab` 으로 옮겼다. 후자와 함께 **조작표를 게임 안에** 넣었다.

### 임성규 — 골격 · 진행 · 상호작용 · 레벨 · 배포 · 운영

**0단계 골격.** 레이어 8종과 물리 충돌 매트릭스, 인터페이스 3종(`IDamageable` ·
`IInteractable` · `IDeviceTrigger`), 폴더 구조, 샌드박스 씬. **세 사람이 동시에
붙을 수 있게 만든 것이 이 단계의 전부다.**

**진행 시스템.** `Chapters` · `GameFlow` · `ChapterExit` · `SpawnPoint` ·
`Checkpoint` · `PlayerDeathWatcher` — 장 전환 · 체크포인트 · 사망 재시작 · 엔딩.

**상호작용과 장치 전량.** `Lever` · `Pickup` · `Carriable` · `CarrySlot` ·
`Readable`, 그리고 장치 3패턴(`InstantDevice` · `TimedDevice` ·
`SustainedDevice`). 기획의 장치 아홉이 이 셋의 파라미터 조합으로 끝난다.

**레벨 넷.** 1장 관제동 · 2장 숙소동 · 5장 외부 철탑, 그리고 6장 초판. 2장 복도는
큐브 모듈로 짓고, 김도한의 Blender 판을 받았다가, 다시 큐브 모듈로 되돌리고,
마지막에 Meshy 소품으로 갈아끼웠다 — **세 번 다시 지은 장이다.**

**월드 에셋 조달.** Meshy 소품 30종을 뽑아 프리팹으로 세웠고, 월드 표면 텍스처
17종을 절차적 생성 스크립트로 만들었다(파일이 아니라 **스크립트가 원본**이다).
스케일 큐브의 텍셀 밀도를 맞추는 `SurfaceTiling` 도 여기서 나왔다. 5장 전용
부품은 `SnowPlow` · `AvalancheShot` · `SearchlightSweep` 이다.

**빌드와 배포.** `gh-pages` 로 나가는 모든 빌드. 2048 텍스처 21장을 1024 로
내려 GitHub 의 100MB 벽을 넘긴 것도 여기다.

**팀 운영.** 역할 배분, `plan.md` 의 단계 설계, AI 개발 환경(`.claude/` 의 훅 ·
규칙 · 스킬), 문서 체계. 게임 코드가 아니라 **셋이 부딪히지 않고 동시에 일하게
하는 쪽**이다.

### 명목 역할과 실제가 달라졌다

이 표가 이 문서에서 가장 값어치 있는 부분이다.

| | 처음 배정 | 실제로 굳은 것 |
| --- | --- | --- |
| **A** 이정범 | 플레이어 · 전투 | 플레이어 + **캐릭터 · 적 리깅 전량** |
| **B** 김도한 | 적 · 에셋 | 적 코드 + **사운드 · 연출 · UI 전량** |
| **C** 임성규 | 상호작용 · 레벨 · 진행 | 그대로 + **골격 · 배포 · 운영** |

가장 크게 갈린 것은 **적**이다. 명목상 적은 B 인데, 실제로는 **B 가 모델링 시트를
만들고 A 가 리깅과 애니메이션을 붙이는 분업**으로 굳었다. `Crawler` · `Colossus` ·
`Clinger` 셋 다 그랬다. 처음부터 정한 것이 아니라 A 가 Blender 파이썬 파이프라인을
먼저 뚫었기 때문에 그렇게 됐다.

**이것을 문서에 안 적었다가 한 번 틀렸다.** 3단계 장별 담당을 정하며 「적은 B
담당이니 `Clinger` 가 나오는 4장도 B」로 배정했는데, 실제로 `Clinger` 를 만든
사람은 A 였다. 지금 이 절이 존재하는 이유다.

## 협업 및 분업 방식

### 브랜치는 `develop` 하나다

작업용 브랜치를 만들지 않고 셋이 같은 브랜치에 직접 커밋한다. 3인 · 단기라
리뷰 대기가 병렬성보다 비싸고, **제출 요건인 커밋 기록도 한 줄로 읽힌다.**
`git pull` 은 항상 `--rebase --autostash` 로 받는다.

### 부딪히는 것을 코드가 아니라 구조로 막았다

Unity 의 씬 · 프리팹 · 프로젝트 설정은 **텍스트지만 병합할 수 없다.** GUID 와
fileID 가 얽혀 있어 겉보기에 맞춰놔도 씬이 조용히 깨진다. 그래서 시작 전에
부딪힐 자리를 먼저 없앴다.

| 자리 | 어떻게 |
| --- | --- |
| 씬 | **한 사람만 만진다.** 남에게는 프리팹으로 넘긴다 |
| 레이어 번호 | 8종을 미리 다 잡고 **담당별로 번호 구간을 나눴다.** 동시에 추가해도 안 겹친다 |
| 충돌 매트릭스 | 처음에 한 번 계산해 넣고 그 뒤로 아무도 안 건드린다 |
| 프롬프트 로그 | **세션마다 파일이 갈린다.** 매 프롬프트가 파일을 고치는데도 충돌이 안 난다 |
| 할 일 목록 | 공유하지 않고 각자 `docs/backlog.local.md` 에 둔다 |

프롬프트 로그가 `git config user.name` 으로 폴더를 가르므로 **커밋 이름이 한글인지
검사하는 훅**을 두었다. 그래도 이정범의 커밋 4개가 영문 이름(`teterschaft`)으로
들어갔는데, **다른 기계에서 작업한 것**이다. 프롬프트 폴더는 셋 그대로여서 기록은
안 갈렸고 커밋 저자만 둘로 보인다. 마감 시점의 커밋 수는 그 둘을 합친 값이다.

### 대기 관계는 계약을 먼저 박아서 끊었다

가장 비싼 것은 충돌이 아니라 **남을 기다리는 시간**이다. 셋이 서로의 완성품을
기다리지 않도록 **인터페이스를 0단계에 먼저 박았다.**

- `IDamageable` 을 A 와 B 가 **각자 먼저 구현했다.** 붙일 때 배선만 남았고,
  실제로 양쪽 다 상대 타입을 모른 채 서로를 때린다
- A 가 `Player.prefab` **껍데기를 완성 전에 커밋했다.** 캡슐에
  `CharacterController` 만 붙은 것이라도 B 의 적은 쫓을 대상이 생기고 C 는
  관통을 확인할 수 있다
- 장치 3패턴을 C 가 먼저 만들어 공유하고, A · B 는 새 스크립트 없이 파라미터만
  바꿔 자기 장에 놓았다

### 문서가 세션 사이의 통신선이다

셋이 각자 Claude Code 세션에서 일하므로 **말로 한 합의는 상대 세션에 없다.**
그래서 결정을 내리면 그 자리에서 문서에 적는다.

| 무엇 | 어디 | 언제 |
| --- | --- | --- |
| 다음에 뭘 만드나 | `docs/plan.md` | 단계가 끝날 때 |
| 구조 규칙 | `docs/tech-design/architecture.md` | 구조를 바꾸는 **같은 커밋**에 |
| 왜 그렇게 정했나 | 각 `decisions.md` | `/decision` |
| AI 를 어떻게 썼나 | `docs/ai/milestones/` | `/milestone` |

`.claude/` 의 규칙과 스킬(`/design` · `/decision` · `/milestone` · `/deploy` ·
`/prop`)은 저장소에 커밋되어 **세 사람의 세션이 같은 절차를 밟는다.** 규칙을
고치면 세 사람에게 동시에 퍼지므로, 고친 사람이 「세션을 다시 열어야 한다」까지
알린다.

### 실제로 부딪힌 것

- **6장 진입로를 두 사람이 각자 지었다.** C 가 5장에서 6장으로 잇는 길을 만든
  것을 A 가 모르고 6장 쪽에서 또 지었다. 겹친 것을 하나로 합치며 각자 나은 쪽을
  남겼다. **씬 소유자 규칙이 있어도 「장과 장 사이」는 주인이 없다**는 것이
  드러난 자리다
- **발소리 구현이 한동안 두 벌이었다.** A 의 `PlayerFootsteps` 와 `PlayerMotor`
  안의 것. 전자를 남기고 걷어냈다
- **적의 청각이 적마다 따로 있었다.** A 가 발견해 B 가
  `PlayerMotor.NoiseRadius` 하나로 합쳤다 — 소리 크기는 **내는 쪽**이 정하고
  반응만 적마다 다르다

### 에디터 작업도 AI 가 한다

씬 · 프리팹 · 머티리얼 · 빌드 설정처럼 손으로 하던 일을 **Unity MCP 로 세션이
직접 한다.** 사람에게 남긴 것은 에디터 밖의 일뿐이다 — Unity Hub, 라이선스,
계정. 이 과제는 AI 활용 자체가 심사 대상이라, 수동으로 넘긴 만큼 근거가
사라지기 때문이다.
