## 작업 분담 — A · B · C

기획 확정(2026-08-08) 후 [`treeline.md`](game-design/treeline.md) 의 「만들
시스템」과 「만드는 순서」를 기준으로 나눴다. 각자 **코어 하나 + 장 하나**다.

순서와 근거는 [`tech-design/decisions.md`](tech-design/decisions.md),
구조 규칙은 [`tech-design/architecture.md`](tech-design/architecture.md) 참고.

이 문서는 **누가 무엇을 맡는가**만 다룬다. 각 단계를 어떤 차수로 쪼개고 무엇을
채워야 끝인지는 [`plan.md`](plan.md) 에 있다. 다음에 뭘 할지 찾을 때는 그쪽을
본다.

### 1단계 — 관통

완료 기준은 **처음부터 끝까지 걸어서 엔딩에 도달하고 죽을 수도 있는 것**이다.
회색 박스여도 된다. 여기까지 되면 즉시 빌드해 배포한다.

| | | 만드는 것 |
| --- | --- | --- |
| **A** | 이정범 | 1인칭 이동 · 카메라 · 손전등 · 체력 3칸 · 권총 1종 · 탄약 · 피격 판정 |
| **B** | 김도한 | 적 1종(기는 것) 추격 · 공격 · 사망. 그리고 AI 모델 생성 → 리깅 파이프라인 검증 |
| **C** | 임성규 | 1 · 2 · 6 회색 박스, 문 · 레버 최소 상호작용, 씬 전환 · 사망 · 재시작 · 엔딩 |

IMPORTANT: **A 는 `Player.prefab` 을 완성 전에 먼저 올린다.** 캡슐에
`CharacterController` 와 `Player` 태그만 붙은 껍데기여도 된다. B 의 적은 추격할
대상이 필요하고 C 의 관통 확인에는 Player 와 Enemy 가 둘 다 필요하다. 1단계에 남은
유일한 대기 관계이므로 여기서 막히면 셋이 같이 선다.

IMPORTANT: **적 모델이 늦어져도 1단계는 진행되어야 한다.** B 는 캡슐로 추격 ·
공격 · 사망까지 완성하고 모델은 나중에 갈아끼운다. 파이프라인 검증이 1단계를
막으면 안 된다.

### 시작하기 — 각자의 첫 걸음

0단계(레이어 · 인터페이스 · 폴더 · 샌드박스 씬)는 2026-08-08 에 들어갔다. 지금
바로 시작할 수 있다.

**공통**

- 작업은 `Assets/Game/<자기 담당 폴더>/` 안에서만 한다. `Shared/` 를 고치는 것은
  셋의 합의가 필요하다
- 실험은 `_Sandbox/<자기 이름>.unity` 에서 한다. 남의 샌드박스를 열지 않는다
- 레이어 번호를 코드에 쓰지 않는다. `Shared/GameLayers.cs` 를 쓴다
- 입력은 신규 Input System 으로만 받는다. `Input.GetKey` 류는 런타임에 예외가 난다
- 의미 있는 것을 끝내면 `/milestone`, 무언가 정했으면 `/decision`

**A 이정범** — `Assets/Game/Player/`

1. `Player.prefab` 껍데기를 먼저 커밋한다. 캡슐 + `CharacterController` +
   `Player` 태그 + `Player` 레이어면 충분하다
2. 자기 샌드박스에서 이동 · 카메라 · 손전등
3. `InputSystem_Actions.inputactions` 를 인수한다. 이 에셋의 소유자는 A 다
4. 사격은 `GameLayers.Shot` 으로 레이캐스트하고 맞은 것이 `IDamageable` 이면 때린다
5. 상호작용 조준은 `GameLayers.Interaction`, 대상은 `IInteractable`

**B 김도한** — `Assets/Game/Enemy/`

1. 자기 샌드박스에 캡슐 두 개를 놓는다. 하나에 `Player` 태그를 붙이면 A 의
   프리팹이 오기 전에도 추격을 만들 수 있다
2. `Crawler.prefab`. `IDamageable` 을 구현하고 레이어는 `Enemy` 다
3. 플레이어는 `FindWithTag("Player")` 로 찾는다
4. 시야 판정은 `GameLayers.EnemySight`
5. NavMesh 는 `com.unity.ai.navigation` 의 `NavMeshSurface` 를 쓴다

**C 임성규** — `Assets/Game/Levels/` · `Interaction/` · `Progress/`

1. `Levels/Ch1.unity` · `Ch2.unity` · `Ch6.unity` 를 만들고 빌드 목록에 등록한다
2. 씬 로드는 인덱스가 아니라 이름으로 한다
3. 문 · 레버는 `IInteractable` 을 구현하고 레이어는 `Interactable` 이다
4. 진행 트리거와 체크포인트 볼륨은 `Trigger` 레이어에 둔다

### 2단계 — 1 · 2 · 6 에 기믹

장을 한 명씩 인수한다. 회색 박스는 C 가 만들었지만 살을 붙이는 것은 각자다.

| | | 담당 장 | 붙이는 것 |
| --- | --- | --- | --- |
| **A** | 이정범 | 6장 승강장 | 삭도 절차, 산탄총, 엔딩 연출 |
| **B** | 김도한 | 2장 숙소동 | 첫 조우 연출, 그리고 `Colossus`(큰 것) |
| **C** | 임성규 | 1장 관제동 | 장치 3패턴 컴포넌트, 배터리, 양손 운반 |

IMPORTANT: **2단계에 만드는 적은 `Colossus` 하나다.** `Clinger`(매달린 것)는 4 ·
5장에 나오므로 3단계다. 기획의 「셋을 동시에 진행하면 셋 다 미완성이 된다」를
적에도 그대로 적용한다. 그리고 `Colossus` 는 A 의 6장이 기다리는 물건이므로 2단계
안에서도 먼저 나와야 한다.

C 가 장치 3패턴 컴포넌트를 먼저 만들어 공유하면, A 와 B 는 파라미터만 바꿔
자기 장에 쓴다.

### 3단계 — 3 · 4 · 5

2026-08-09 에 배정했다. 5장이 컷라인 1순위라는 기획의 판단은 그대로 유지한다.

| | | 담당 장 | 왜 |
| --- | --- | --- | --- |
| **A** | 이정범 | **4장 발전동** | **`Clinger` 의 에셋과 애니메이션을 A 가 처음 넣는다.** 4장은 그것이 전부인 장이고, 천장에서 떨어지는 동작은 클립과 레벨이 서로 맞아야 한다. 만든 사람이 놓는 것이 맞다 |
| **B** | 김도한 | **3장 연료 갱도** | **총기 시스템이 이미 들어가 있어** 이 장이 무기 구현을 기다리지 않는다. 남은 것은 통로 구조 · 연료 배치 · 인화 연출인데, 불은 B 가 만든 파티클 키트가 그대로 쓰인다 |
| **C** | 임성규 | **5장 외부 철탑** | 컷라인 1순위라 마지막에 붙인다. 자를 때 C 의 작업만 버려지므로 A · B 의 진행을 막지 않는다 |

**2 · 3단계에서 실제 작업이 명목 역할과 달라진 것을 반영했다.** A 는 캐릭터 리깅과
애니메이션(전신 리그 · 1인칭 팔 17종 · `Colossus` 15종)으로, B 는 배경 · 연출 ·
사운드 · VFX(타이틀 · 엔딩 설원, 파티클 키트, 적 소리)로, C 는 레벨 구축(1 · 2 · 6 ·
Meshy 소품 30종 · 표면)으로 굳었다. 배정은 그 자리를 따랐다.

IMPORTANT: **적 리깅은 이제 A 다.** 명목 역할에서 적은 B 이지만 실제로는 B 가
모델링 시트를 만들고 **A 가 리깅과 애니메이션을 붙이는 분업**으로 굳었다
(`Crawler` · `Colossus` 둘 다 그랬다). 4장이 A 로 간 근거가 그것이다.

IMPORTANT: **C 는 3 · 4장이 끝난 뒤에 5장을 시작한다.** 그전까지 통합 · 배포와
4단계(제출물)를 준비한다. 5장을 먼저 잡으면 컷라인 후보에 사람이 묶이고, 정작
잘라야 할 때 남은 둘이 덜 완성된 채로 남는다.

5장이 붙으면 **6장에 제설포 피날레와 시점 전환 컷을 얹어야 하는데, 6장의 실질
소유도 C 로 넘어와 있다.** 같은 사람이 하므로 대기 관계가 생기지 않는다.

야외 설원은 **B 가 타이틀 · 엔딩에서 만든 것을 프리팹으로 넘겨받는다.** 5장에서
가장 비싼 부분이 이미 만들어져 있다.

IMPORTANT: **A 는 레벨을 처음부터 지어본 적이 없다.** 1 · 2 · 6 은 C 와 B 가 지었다.
막히면 혼자 붙들지 말고 말한다. 다만 그사이 진입 장벽이 많이 낮아졌다 — Meshy 소품
프리팹 30종, `SurfaceTiling`, `/prop` 절차, 그리고 참고할 장이 셋 있다.
