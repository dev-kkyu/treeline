# 개발 단계

무엇을 만들지는 [`game-design/treeline.md`](game-design/treeline.md), 누가 맡는지는
[`roles.md`](roles.md), 구조 규칙은
[`tech-design/architecture.md`](tech-design/architecture.md) 에 있다. 이 문서는
**그것을 어떤 순서로 쪼개어 만드는가**만 다룬다.

## 이 문서를 쓰는 법

- 한 단계는 **남이 봐도 끝났는지 아는 완료 기준**을 갖는다. "만든다" 가 아니라
  "이렇게 되면 끝" 으로 적는다
- 한 차수 안의 항목은 병렬로 해도 되지만, **차수는 건너뛰지 않는다.** 앞 차수의
  완료 기준을 못 채운 채 다음으로 가면 뒤에서 한꺼번에 터진다
- 끝난 항목은 지우지 말고 체크한다. 무엇을 했는지가 제출물의 재료다
- **「내 샌드박스에서 된다」는 완료가 아니다.** 완료 기준은 언제나 실제로 놓일
  자리에서 확인한다. 1-2 가 정확히 그 자리다 — 적이 B 의 샌드박스에서는 쫓아오고
  레벨 씬에서는 굳어 선다

IMPORTANT: 단계 구분(0 · 1 · 2 · 3)은 [`roles.md`](roles.md) 와
[`tech-design/decisions.md`](tech-design/decisions.md) 가 이미 참조하고 있다.
번호를 바꾸지 않는다. 잘게 나눈 것은 그 안의 **차수**다.

## 전체 지도

| 단계 | 무엇 | 끝나면 |
| --- | --- | --- |
| **0** | 골격 — 레이어 · 인터페이스 · 폴더 · 샌드박스 | 세 사람이 동시에 붙을 수 있다 ✅ |
| **1** | 관통 — 1 · 2 · 6 을 회색 박스로 | **제출 가능한 상태가 된다** ← 지금 여기 |
| **2** | 1 · 2 · 6 에 기믹 | 완결된 짧은 게임이 된다 |
| **3** | 3 · 4 · 5 를 가운데 끼운다 | 기획대로의 게임이 된다 |
| **4** | 제출물 | 낸다 |

IMPORTANT: **1단계가 끝나는 순간부터 언제 멈춰도 완결이다.** 자르는 순서는 5장 →
4장 → 3장이고, 이 판단은 기획에 적힌 대로 유지한다.

## 1단계 — 관통 · 진행 중

**완료 기준:** 타이틀에서 시작해 1 → 2 → 6 을 걸어 엔딩에 도달한다. 도중에 죽을
수 있고, 죽으면 그 장의 처음에서 다시 시작한다. 회색 박스여도 된다.

2026-08-08 에 **1-1 · 1-2 · 1-3 이 끝났다.** 남은 것은 **배포뿐**이다.

### 1-1 각자 혼자 돌아가는 것 ✅

| | 한 것 |
| --- | --- |
| **A** | `Player.prefab` 선행 커밋 → 이동 · 달리기 · 웅크리기 · 점프 · 카메라 · 손전등 · 체력 3칸 · 무기 · 상호작용. `IDamageable` |
| **B** | `Crawler.prefab` — NavMesh 추격 · 공격 · 사망. `IDamageable`. 적 3종 모델링 시트 |
| **C** | `Ch1` · `Ch2` · `Ch6` · `Ending` 회색 박스, 빌드 목록 등록 |

여기서 지킨 두 가지가 실제로 값을 했다. **`Player.prefab` 을 완성 전에 올린 것**과
**`IDamageable` 을 양쪽이 각자 먼저 구현한 것.** 1-2 가 배선만 남는 차수가 됐다.

### 1-2 서로 붙이기 ✅

세 장에 `NavMeshSurface` 를 놓고 굽고 `Crawler.prefab` 을 배치했다 (`884d076`).

**순서가 값을 했다. NavMesh 를 먼저 굽고 적을 놓았다.** 반대로 했으면 적이 그 자리에
굳어 서고, 증상이 프리팹 문제로 보여서 B 가 자기 코드를 뒤졌을 것이다. B 의
샌드박스에서는 구워져 있어 잘 돌아가기 때문이다.

굽는 방법의 함정 둘 — **캐릭터를 빼고 굽는 것**과 **구운 데이터를 씬에 묻지 않는
것**(묻으면 씬 파일이 통째로 바이너리가 된다) — 은
[`tech-design/architecture.md`](tech-design/architecture.md) 의 「NavMesh 는 캐릭터를
빼고 굽는다」에 있다.

**A 가 완료 기준을 양방향으로 확인했다 (2026-08-08).** 권총 2발에 `Crawler` 가
죽고(체력 2 · 1피해와 일치), `Crawler` 가 7프레임 만에 추격을 시작해 세 번 때려
플레이어를 죽이고 `PlayerHealth.Died` 까지 발생한다. **양쪽 다 상대 타입을 모른 채
`IDamageable` 로만 닿는다.** 대역이 아니라 B 의 실제 프리팹으로 확인했다.

### 1-3 관통 잇기 — C ✅

장 전환(이름 기반) · 체크포인트 · 사망 재시작 · `Ending` 씬. `EditorApplication.Step`
으로 프레임을 밀며 세 구간 전환과 사망 · 부활까지 확인했다.

사망 통지는 처음에 `IDamageable.IsAlive` 폴링으로 두었다가 A 의 `PlayerHealth.Died`
가 생기면서 구독으로 바꿨다. **임시 방편을 한 컴포넌트에 가둬 둔 덕에 파일 하나를
지우는 것으로 끝났다.**

타이틀 화면(`3092506`)과 6장 삭도 기동 레버(`6d2f600`, `IInteractable` 첫 구현체)도
들어왔다. `Ending` 은 아직 검은 화면뿐이라 2단계에서 채운다.

IMPORTANT: **6장 절차는 이 단계에서 레버 하나뿐이다.** 가운데 장이 붙을 때마다 한
단씩 늘린다. 처음부터 전부 만들면 3 · 4 · 5 를 자를 때 배운 적 없는 장치를 쓰게
된다.

### 1-4 배포 — 남음

빌드와 배포는 **C(임성규)가 맡는다.** 배포 경로를 뚫은 사람이고, 산출물이
`gh-pages` 에 쌓이므로 한 사람이 쥐는 편이 낫다.

지금 배포 주소에 올라가 있는 것은 **빈 프로젝트 빌드**(`aaf279d`)다. 앞 차수가 다
끝났으므로 **이것만 하면 1단계가 닫힌다.**

- WebGL 빌드 (출력은 반드시 `Treeline/Build/`)
- 로컬 웹서버로 확인 → `/deploy`
- [`game-design/overview.md`](game-design/overview.md) 의 플레이 링크를 채운다
- 각자 `/milestone`

**완료 기준:** 배포 주소에서 처음부터 끝까지 플레이된다. **여기서부터 제출
가능한 상태다.**

## 2단계 — 1 · 2 · 6 에 기믹

**완료 기준:** 세 장이 기획에 적힌 시나리오대로 진행된다. 회색 박스가 아니다.

### 2-1 공용 부품 — 남이 기다리는 것부터

이 차수가 끝나야 2-2 를 병렬로 할 수 있다.

| | 만드는 것 | 누가 기다리나 |
| --- | --- | --- |
| **C** | 장치 3패턴 컴포넌트 — 즉시 발동 / 시간 발동 / 지속 상태. `IDeviceTrigger` | A · B 가 파라미터만 바꿔 쓴다 |
| **C** | 양손 운반 (들면 총을 못 쓴다) | A 의 6장 권양기 |
| **C** | 손전등 배터리 소모 · 줍기 | 2장의 어둠이 성립한다 |
| **A 이정범** | 달리기 스태미너 소모 · 회복 대기 · HUD 연결 | 2장과 6장의 도망 구간 |
| **B** | `Colossus.prefab` — 죽지 않고 밀려나기만 한다 | A 의 6장 |

**완료 기준:** A 와 B 가 새 스크립트를 쓰지 않고 자기 장에 장치를 놓을 수 있다.

IMPORTANT: **이 차수를 시작하기 전에 계약 두 개를 정한다.** 둘 다 C 가 만드는데
효과는 A 의 코드에서 나므로, 정하지 않으면 양쪽이 각자 만들어 두 벌이 된다.

- **양손 운반 ↔ 총 봉인.** 운반하는 쪽(C)이 `WeaponSwitcher.SetCarrying(bool)` 을
  부른다. 들면 총을 내리고 내려놓으면 원래 총으로 돌아온다.

  > **확정 (2026-08-08).** 처음에는 반대로 적었다 — C 가 상태를 노출하고 A 가
  > 그것을 보는 쪽. 근거는 「C 가 무기 시스템을 알게 된다」였는데, **C 가 아는
  > 것은 bool 하나뿐이라 그 일이 실제로는 생기지 않는다.** 오히려 뒤집으면 A 가
  > 아직 없는 C 의 타입을 참조하게 되어 새 대기 관계가 생긴다. 게다가 바깥이
  > Player 의 함수를 부르는 자리가 이미 셋 있어(`TakeDamage`, `AddBattery`,
  > `Restore`) 같은 모양이다. 전체 근거는
  > [`tech-design/decisions.md`](tech-design/decisions.md) 의 「무거운 것을 들면
  > 총을 못 쓴다」 항목.

- **배터리 ↔ 손전등 — 정해졌다 (2026-08-08).** 줍는 쪽이
  `Flashlight.AddBattery(초)` 를 부른다. 초 단위 숫자만 넘기고 용량을 넘는 분은
  A 가 버린다. 원래 적힌 방향과 같아서 고칠 것이 없었다.

- **획득 ↔ 소지 — 정해졌다 (2026-08-08). A 쪽은 이미 들어갔다.** 손전등 · 권총 ·
  산탄총이 셋 다 「주워야 쓴다」로 통일됐다. C 는 획득물에서 아래를 부르면 된다.

  | 언제 | 부를 것 |
  | --- | --- |
  | 1장 손전등 | `Flashlight.PickUp()` |
  | 3장 권총 · 5장 산탄총 | `WeaponSwitcher.PickUp(WeaponKind)` |
  | 탄약 | `WeaponSwitcher.AddAmmo(종류, 발수)` |
  | 배터리 | `Flashlight.AddBattery(초)` |

  **총과 탄약은 따로다.** 총을 안 주웠어도 탄약은 쌓이므로 「탄약만 먼저 발견」
  같은 배치가 된다. 근거는
  [`tech-design/decisions.md`](tech-design/decisions.md) 의 「주워야 쓴다」 항목.

  IMPORTANT: 이건 원래 2-1 로 잡혀 있었는데 **1단계에서 이미 어긋나 있어서**
  앞당겼다. `Ch1` 에 놓인 `Player.prefab` 이 손전등을 갖고 시작하고 있었다.
  프리팹 기본값이 이제 전부 미획득이라 C 는 획득물만 붙이면 된다.

- **달리기 ↔ 스태미너 HUD — A 이정범 작업.** `PlayerMotor`가 실제 달리는 동안만
  스태미너를 줄이고, 달리기가 끝난 뒤 1.5초 동안 회복을 막은 다음 회복한다.
  초기값은 연속 달리기 5초, 완전 회복 3초이며 Inspector에서 조절한다. 0이면 걷기로
  바뀌고 20% 이상 회복해야 다시 달린다. 0~1 비율과 회복 대기 상태를 이벤트로
  노출해 `Assets/Game/UI/Art/HUD/Stamina/`의 게이지와 연결한다. 완료 기준은 A의
  샌드박스에서 소모·대기·회복·고갈·재개 제한이 모두 보이는 것이다.

### 2-2 각자 장 — 병렬

**C · 1장 관제동** — 둘러본다

- 서치라이트 (지속 상태 장치). 위험하지 않을 때 먼저 만져본다
- 무전 일지, 근무표 (**숫자가 3장 캐비닛 번호다**)
- 창밖으로 지나가는 실루엣 (**6장 큰 것의 예고**)

  이것은 어두운 창밖을 지나가는 그림자 연출이면 된다. **B 의 `Colossus.prefab` 을
  기다리지 않는다.** 눈보라 사이로 잘못 본 것 같은 정도라 실물이 필요 없고,
  기다리면 C 의 1장이 B 에 묶인다.

**B · 2장 숙소동** — 숨고 버틴다

- 정전. 손전등만. **무기를 주지 않는다**
- 켜야만 하는 상황 → 켜니까 거기 있다 (갑자기 튀어나오는 것이 아니다)
- 얼어붙은 문 → 히터 케이블 (시간 발동) → 그동안 숨어서 버틴다
- 비상 셔터 레버로 끊고 빠져나간다
- 도망칠 길은 **하나**여야 한다. 미로면 길 찾다 죽는다

**A · 6장 승강장** — 도망치며 절차를 밟는다

- `Colossus` 등장. 총이 통하지 않는다
- 케이블 히터를 켜고 녹는 동안 숨는다 (2장에서 배운 것)
- 삭도가 출발하고 **화면이 뒤집힌다**

IMPORTANT: **이 단계의 6장에 제설포는 없다.** 제설포는 5장에서 배우는 물건이라
3-3 에서 피날레로 붙인다. 지금 넣으면 3 · 4 · 5 를 잘랐을 때 배운 적 없는 장치로
게임이 끝난다. 기획이 「잘라도 6장은 삭도가 출발하고 화면이 뒤집힌다로 그대로
끝난다」고 못 박은 이유다.

**완료 기준:** 각 장을 처음부터 끝까지 플레이해 기획의 장면이 그대로 나온다.

### 2-3 통합 점검 · 재배포

- 관통을 다시 확인한다 (장마다 따로 되던 것이 이어서도 되는가)
- 재배포, `/milestone`

## 3단계 — 3 · 4 · 5 를 가운데 끼운다

한 장씩 완성한다. 셋을 동시에 하면 셋 다 미완성이 된다. 순서는 비용이 낮은
순서다.

IMPORTANT: **장을 하나 붙일 때마다 6장 절차를 한 단 늘린다.** 이것을 빠뜨리면
가운데를 자를 때 배운 적 없는 장치가 6장에 남는다. 장 작업과 6장 갱신은 **같은
차수**에서 끝낸다.

| 완성된 장 | 6장 절차 |
| --- | --- |
| 1 · 2 · 6 | 히터 → 출발 |
| **+ 3** | 연료 → 히터 → 출발 |
| **+ 4** | 연료 → 히터 → 배전반 → 출발 |
| **+ 5** | 위 + 마지막에 제설포로 사면을 무너뜨린다 |

### 3-1 · 3장 연료 갱도 — 처음 쏜다

- 경비 캐비닛에서 권총 획득. 번호는 **2-2 에서 C 가 1장에 심어둔 근무표 숫자**와
  맞춘다. 이 시점에 1장을 다시 열 일은 없어야 한다
- 어둠 속 총구 섬광
- 연료통 운반 (2-1 의 양손 운반). 내려놓고 쏘고 다시 든다
- 고인 연료에 쏘면 인화. **태우면 다시 구해야 한다**
- 셔터 재등장
- 장 끝에 천장에서 소리 (**4장 매달린 것의 예고**)
- **6장 절차에 「연료」 를 앞에 붙인다**

### 3-2 · 4장 발전동 — 버틴다

- `Clinger.prefab` — 천장에서 떨어진다
- 차단기 두 개. 흩어져 있어 돌아다닌다
- 축전지실 수소 — **여기서 쏘면 터진다.** 환기 팬(시간 발동)으로 빼거나 그냥 들어간다
- 발전기 기동 레버 → 예열 동안 몰려온다
- 전력 복구 → **조명이 켜지고 공간 전체가 드러난다**
- **6장 절차에 「배전반」 을 넣는다**

### 3-3 · 5장 외부 철탑 — 이동하며 싸운다

**컷라인 1순위다.** 여기가 안 되어도 게임은 완결이다.

- 눈보라. 하얘서 안 보인다 (어둠과 반대)
- 산탄총 획득

## 누락되기 쉬운 것 — 장을 가로지르는 연결

각 장을 따로 만들면 **심어놓고 거두지 않거나, 거두는데 심은 적이 없는** 상황이
생긴다. 장 작업을 끝낼 때 이 표에서 자기 장이 나오는 줄을 확인한다.

| 심는 곳 | 거두는 곳 | 무엇 |
| --- | --- | --- |
| 1장 | **3장** | 근무표 숫자 = 경비 캐비닛 번호 |
| 1장 | **5장** | 서치라이트를 안전할 때 먼저 만져본다 |
| 1장 | **6장** | 창밖 실루엣 = 큰 것 |
| 2장 | 3장 | 셔터 재등장 |
| 2장 | **6장** | 히터로 기다리는 구간 |
| 3장 | 4장 · **6장** | 연료 운반 |
| 3장 | 4장 | 장 끝 천장 소리 = 매달린 것 예고 |
| 4장 | **6장** | 배전반 |
| 5장 | **6장** | 제설포 |

**굵은 것은 6장으로 모인다.** 6장은 새로 배우는 것이 하나도 없는 장이므로, 앞
장이 바뀌면 반드시 6장을 다시 본다. 그리고 **6장을 고치는 것은 언제나 6장
소유자다.** 3단계 담당이 누구든 자기 장만 만들고 6장 갱신은 소유자에게 넘긴다.

IMPORTANT: **재등장하는 장치는 씬에 직접 만들지 말고 프리팹으로 만든다.** 위 표의
왼쪽 칸에 있는 것은 전부 다른 장에서 다시 쓰인다. 2장 셔터를 씬 안에 조립해 두면
3장에서 다시 만들게 되고, 두 벌이 되는 순간 한쪽만 고쳐진다. 남에게 넘길 생각이
없어도 **다시 나올 것이면 프리팹**이다.
