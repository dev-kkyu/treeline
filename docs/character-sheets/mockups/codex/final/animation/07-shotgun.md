# 07 · 산탄총

![키포즈](07-shotgun-keyposes.png)

보드의 회색 산탄총은 4발 펌프액션 파지 프록시다. 최종 무기 모델을 선택해도 오른손
grip, 왼손 pump, 오른쪽 shoulder socket 세 기준점은 유지한다.

| 클립 | 프레임 | 손·이벤트 계약 |
| --- | ---: | --- |
| `Player_ShotgunEquip` | 18f | 0 아래, 14 견착, **16 WeaponReady**, 18 Idle |
| `Player_ShotgunIdle` | 60f loop | 개머리판 우측 어깨, 총구 조준점 아래 9°, 왼손 pump |
| `Player_ShotgunFirePump` | 30f | **1 Fire**, 3 +3.4° 반동, 10 pump unlock, 15 후퇴, **16 Eject**, 23 전진·장전, 30 Idle |
| `Player_ShotgunReload` | 78f | 0 안쪽 roll, 12 포트 노출, 18/32/46/60 shell pose, **68 TubesClosed**, **78 ReloadComplete** |

- 현재 발사 간격은 0.9 shots/s, 약 33.3f다. 30f 액션 뒤 최소 4f cooldown을 코드가 보장한다.
- 카메라 반동 3.4°/±1.2°와 팔 반동이 합쳐진다. 팔에는 처음 45%만 넣었는데 둘 다
  돌려보니 **팔 쪽이 안 보였다.** 1.5배로 올려 총구가 f3 에 **8.1° 들린다**
  (f1 0° → f3 8.1° → f6 3.7° → f10 0°). 45% 는 어느 쪽도 만들어지기 전에 적은
  값이다.
- 재장전 코드는 2.6초 끝에서 필요한 탄을 일괄 충전한다. 시각상 4개 shell pose가 있어도
  중간 취소 시 일부 탄이 들어가지 않는다. 부분 장전을 구현하기 전까지 이 계약을 유지한다.
- Fire가 Reload보다 우선하지 않는다. 재장전 중 발사 입력은 무시하는 현재 코드와 맞춘다.
- Crouch에서는 개머리판 위치를 유지하고 팔꿈치만 4cm 위로 보정해 무릎 관통을 막는다.

## 팔이 이 산탄총에 짧다 (2026-08-09)

손 포즈를 풀면서 나왔다. 권총과 같은 자리에서 들면 **펌프가 카메라 앞 0.81 m 에
놓이는데 왼팔은 어깨부터 손끝까지 0.595 m 라 279 mm 모자란다.** 손잡이 웹에서
펌프 중앙까지가 0.46 m 이고([`09-weapons.md`](09-weapons.md)) 어깨 사이가 0.31 m
라, **총구를 왼쪽 아래로 눕히고 손잡이를 몸 가까이 두어야** 왼손이 펌프에 닿는다.

`Player_ShotgunIdle` 의 「개머리판 우측 어깨」는 이 모델에 개머리판이 없으므로
해당하지 않는다. 견착 대신 **몸 앞 낮은 자세**로 만든다.

### 기준 자세 (2026-08-09, 두 번 정정)

처음에 「손잡이 웹 `(0.16, −0.06, −0.36)`, 총구 `(−0.55, −0.80, −0.24)`」로 적었다.
점 사이 거리만 계산한 값이라 **손이 손목이 아니라 물갈퀴로 놓인다**는 것을 빼먹었고,
리그로 재니 손목이 38° 로 상한을 넘었다.

그다음 「양손 파지가 아예 성립하지 않는다」고 적었다. **그것도 틀렸다.** 자세를
훑던 코드가 손목 위치를 **그립 점**과 비교하고 있었는데, 그 둘은 구조상 56 mm
떨어져 있다. 그래서 어떤 자세를 넣어도 똑같이 ~53 mm 어긋난다고 보고했고 그것을
도달 실패로 읽었다. 비교 대상을 손목 목표로 고치니 **486 자세 중 274 개가
성립한다.**

확정값은 아래다. `find_stance.py` 가 도달 · 손목 · 화면 안에 들어오는 비율을 같이
보고 고른다.

| | 값 |
| --- | --- |
| 손잡이 웹 | `(0.06, −0.22, −0.18)` |
| 총구 방향 | `(−0.70, −1.00, −0.40)` |
| 롤 | 45° |
| 화면에 나오는 비율 | 산탄총 83 %, 펌프 100 % (FOV 80) |
| 최악 손목 | 34.7° (상한 35) |

**팔 길이는 그대로다.** 늘릴 필요가 없었다. `build_arms.py` 에 `ARM_EXTENSION`
손잡이만 0 으로 남겨두었다 — 나중에 정말 안 들어가는 무기가 오면 그때 쓸 자리다.

### 자세를 레퍼런스 사진 기준으로 다시 잡았다 (2026-08-09)

도달 · 손목 · 화면 비율만 보고 고른 자세는 총이 **기울어진 채 멀리** 있었다.
사진에서 펌프건은 몸 앞에 **수평으로** 놓인다 — 굴리는 것은 포트를 여는 재장전
비트지 Idle 이 아니다.

| | 값 |
| --- | --- |
| 손잡이 웹 | `(0.14, −0.10, −0.14)` |
| 총구 방향 | `(−0.45, −1.00, −0.06)` |
| 롤 | **0°** |

`find_stance.py` 가 보는 것이 넷으로 늘었다 — 크기 · 화면 위치 · 수평 · 총열 방향.
도달과 손목은 **통과 조건**이지 목표가 아니다.

### 확정 자세 — 좌우와 렌즈를 고친 뒤 (2026-08-09)

위 두 표의 x 부호는 `.R` 이 +x 에 있던 시절 값이라 그대로는 못 쓴다. 캐릭터의
오른쪽은 −x 이고([`00-rigging.md`](00-rigging.md)), 구도를 보는 렌즈도
`ViewModelCamera` 의 수직 50° · near 0.01 이다.

| | 권총 | 산탄총 |
| --- | --- | --- |
| 손잡이 웹 | `(−0.14, −0.24, −0.10)` | `(−0.22, −0.14, −0.12)` |
| 총구 방향 | `(0.20, −1.00, 0.06)` | `(0.60, −1.00, −0.02)` |
| 롤 | 0° | 0° |
| 화면에 나오는 비율 | 81 % | 73 % |
| 최악 손목 · 회내 | 38.0° · 69.3° | 15.1° · 68.8° |

**화면 오른쪽은 −x 다.** 카메라가 −y 를 보고 +z 가 위이므로 오른손 벡터가 −x 인데,
`screen()` 이 월드 x 를 그대로 화면 x 로 보고했다. 그래서 산탄총의 목표 화면 위치와
탐색 격자가 **화면 반대쪽에 있었고**, 펌프가 프레임 밖으로 나갔다.

### 재장전은 굴리는 것만으로 부족하고 내밀어야 한다 (2026-08-09)

포트가 리시버 아래에 있어서 6° 만 굴린 재장전은 **탄이 화면 아래 밖에서** 들어갔다.
2 초 동안 총이 가만히 있는 클립이 된다.

굴림만 키우면 오른손목이 무너진다 — 55° 에서 113° 였다. 원인은 굴림이 아니라
거리다. Idle 에서 리시버는 눈에서 0.16 m 이고 그 밑면은 시선축 **아래 47°** 라,
수직 반각 25° 짜리 프레임에는 어떤 롤을 줘도 안 들어온다.

| | 값 |
| --- | ---: |
| 앞으로 | 0.16 m |
| 위로 | 0.06 m |
| 안쪽으로 | 0.03 m |
| 롤 | 20° |
| 그때 오른손목 | 47.0° |

롤 **부호는 재서 정한다.** 총이 −x 에 있고 카메라가 원점이므로 카메라는 +x 면을
본다. 포트는 무기 로컬 −z 이고, 총구 축 둘레의 **양의 회전이 −z 를 +x 로** 보낸다.

IMPORTANT: 내민 자리는 **왼팔이 펌프에 못 닿는 자리이기도 하다.** 마지막 탄이
들어간 뒤 f61~67 에 걸쳐 총을 도로 당기면서 왼손을 펌프로 보낸다. f68 까지 내민
채로 두었더니 왼손목이 86° 였다.

**총은 왼손이 떨어진 뒤에 움직이기 시작한다.** 둘을 같이 램프로 주면 아직 펌프를
쥐고 있는 손에서 펌프를 빼앗아 가고, 왼쪽 팔꿈치가 그걸 쫓아 어깨보다 103 mm 위로
올라간다. 돌아올 때도 같다 — 총이 거의 제자리에 온 마지막 프레임에서야 손이
펌프를 다시 잡는다.

## 펌프를 당길 때 총을 5 cm 내민다 (2026-08-09)

실총은 총이 서 있고 손이 움직이지만, 그 손이 70 mm 움직여 가는 어깨가 이미 사거리
끝이다. 왼쪽 팔꿈치가 어깨 위로 올라가고 팔뚝이 82° 돌아갔다. 사람도 펌프를 당길
때 총을 앞으로 밀어 버틴다. 스트로크에 맞춰 0.05 m 내미니 회내 최악이 64.8° 로
들어왔다.

**펌프 왕복은 매 프레임 키잉한다.** 키 두 개로 건너뛰면 양 끝이 70° 아래인데 중간이
114° 가 된다. 팔꿈치는 보간되는 값이 아니라 **매 프레임 다시 맞추는** 값이다.

### 예전 기준: 여유를 보고 골랐다

`find_stance.py` 는 처음에 화면 비율만 최대화해 손목 34.7° 짜리(상한 35)를 골랐다.
**통과했지만 여유가 없어서**, 클립이 총을 굴리기 시작한 세 번째 프레임에서 넘었다.
점수에 여유 항을 넣어 다시 고른 것이 위 표의 값이고, 같은 화면 비율에 손목이
19.7° 다.

**통과선에 걸친 값은 정적 포즈에서만 통과다.** 클립이 그 위에 움직임을 얹는다.

### 탄은 손에 맞춰 눕고 포트로 가며 정렬한다

`Shell` 본이 `WeaponRoot` 자식이라 **주머니에 있는 동안에도 총의 롤을 물려받는다.**
손이 「총에 맞춰 누운 탄」을 잡으라는 요구를 받아 왼손목이 82° 였다. 주머니에서는
탄이 rest 방향으로 서 있고 포트로 가며 총에 정렬되게 키잉한다.

정렬은 **70 % 까지만** 간다. 손가락이 아직 감겨 있는 채로 총열과 완전히 나란하게
만들면 손목이 다시 47° 로 올라간다. 실제로도 탄은 약간 기운 채로 엄지에 밀려
들어간다. 나머지 30 % 는 손이 떨어진 뒤, 탄이 총 안에 들어가 안 보일 때 붙는다.

### 원통은 비틀림이 아니라 축 둘레 각도로 잡는다

탄이나 펌프처럼 원통을 쥘 때 **자유도는 손바닥 법선을 축으로 한 비틀림이 아니라
원통 자신의 축 둘레 각도**다. 어느 각도로 잡아도 손가락은 똑같이 감기고, 손목은
전혀 다른 자리에 온다. 포즈 라이브러리가 푼 한 각도에 고정하면 총이 굴러간 자리에서
답이 없다. `grip_around` 이 축 둘레를 훑어 고른다.

## 재장전 끝에 펌프를 한 번 왕복한다 (2026-08-09)

명세에는 없고 코드는 2.6 초 끝에 튜브를 일괄 충전하지만, **탄창이 빈 상태로 쏘다
재장전하면 약실이 비어 있다.** 마지막 탄이 튜브에 들어간 뒤 액션을 안 걸고 Idle 로
돌아오면 장전된 것처럼 보인다.

| 프레임 | |
| ---: | --- |
| 2~12 | 안쪽으로 눕히며 왼손이 펌프에서 주머니로 (매 프레임 키잉) |
| 18 · 32 · 46 · 60 | 탄 4발 장전 |
| 61~68 | 왼손이 펌프로 복귀 (**68 TubesClosed**) |
| 69~72 | 펌프 70 mm 후퇴 (**72 PumpBack**) |
| 73~76 | 전진 · 장전 (**76 PumpClosed**) |
| 78 | Idle 과 일치 (**78 ReloadComplete**) |

실측 펌프 왕복 65 mm, 왼손이 66 mm 따라간다.
